### 🔴 권한을 선언하면 하드웨어 기능이 **자동으로 필수**가 된다 (2026-08-17에 찾아 고쳤다)

`aapt2 dump badging`으로 보면 매니페스트에 없는 줄이 나온다:

```
uses-implied-feature: name='android.hardware.camera'
    reason='requested android.permission.CAMERA permission'
uses-implied-feature: name='android.hardware.location'
    reason='requested ACCESS_COARSE_LOCATION, and requested ACCESS_FINE_LOCATION'
```

**암시된 기능은 `required=true`다.** 그래서 매니페스트가 일부러 `camera.any`(앞·뒤 아무
카메라)로 열어 뒀는데도 Play는 **뒷면 카메라와 위치 하드웨어를 가진 기기에만** 앱을 보여
주고 있었다. 위치는 이 앱에서 없어도 되는 것이다(장소명만 안 붙고 화면 03이 안내한다).

🔴 **앱 안에 증상이 0이다.** 빌드·설치·22화면·테스트 전부 초록이고, 손해는 "그 기기의
스토어에서 검색되지 않는다"로만 나타난다 — **내 폰으로는 원리상 못 본다.**
🔵 고침은 매니페스트에 `required="false"`를 **명시**하는 것뿐이다(5줄 · 지우면 다시
자동으로 필수가 된다). 고친 뒤 산출물에서 다시 재니 필수 기능이 **둘**만 남았다.
🔵 검사도 같이 고쳤다 — `check_release_artifact.py`가 이제 **badging으로** 권한 집합과
필수 기능을 본다. 예전 판은 `android.permission.*`만 정규식으로 훑어서
**다른 네임스페이스의 권한(`…gms.permission.AD_ID`)이 보이지 않았고** 암시된 기능은
아예 안 봤다. 고친 검사를 **고치기 전 산출물**에 돌려 빨간 줄 2개를 먼저 확인했다.

⚠️ **폭이 6.2MB뿐이다.** 밀도 분할이 거의 아무것도 줄이지 않는다(밀도 차 0.4MB · ABI 차
6.4MB) — 크기의 대부분은 **밀도로 안 갈리는 asset**(일러스트 2,044장)이다. 나중에 줄일
일이 생기면 손댈 곳은 리소스가 아니라 asset이다.

```sql
select u.id, u.created_at::date as 만든날,
       coalesce(p.nickname,'(없음)') as 닉네임,
       (select count(*) from public.discoveries d where d.user_id = u.id) as 기록,
       (select count(*) from public.discoveries d
         where d.user_id = u.id and d.photo_url is not null)             as 서버사진,

          from public.discoveries d where d.user_id = u.id)              as 장소들
  from auth.users u
  left join public.users p on p.id = u.id
 where u.is_anonymous is true
   and u.id::text not like 'a31bcf09%'   -- 🔒 보존 지시받은 계정

```

### 4-9. 🔴 테스터 안내에 **이 문장이 없으면** 14일 카운트가 깎인다 (2026-09-08 실측)

GitHub에 공개 릴리스가 하나 있다 — `catchflower-v1.0.apk` (110MB · **내려받기 집계 2회** ·
`캐치플라워 v1.0 (해커톤 예선 제출)`). ⚠️ **그 2회는 「폰 2대에 깔려 있다」가 아니다** —
내가 뜯으려고 내려받은 것이 그 안에 들어 있고, 파일째 옮겨 간 사람은 집계에 안 잡힌다.
**깔려 있는 대수는 밖에서 셀 수 없으므로 아래 안내문은 테스터 전원에게 보낸다.**
소개 페이지 맨 위에
`APK 내려받기 (Android) — 가장 빠름` 버튼으로 걸려 있다. **두 산출물을 다 뜯어서 쟀다:**

| | 서명 주체(DN) | 인증서 SHA-1 | package · versionCode |
|---|---|---|---|
| GitHub Releases의 APK | `CN=Android Debug` | `55b6f56270686ecabe08bc1f877c6736056ce9af` | `com.catchflower.app` · **1** |
| 올릴 릴리스 빌드 | `CN=CatchFlower, … C=KR` | `62b672e597a3f3c5790aeb86d23482b17075cd90` | `com.catchflower.app` · **1** |

```bash
apksigner verify --print-certs <apk>          # 두 줄이 이 표의 근거다
aapt2 dump badging <apk> | head -1            # package·versionCode가 같은 것
```

🔴 **패키지와 versionCode가 같은데 서명이 다르다** → 안드로이드는 덮어 설치하지 않는다.
예전 APK가 깔린 폰에서 **스토어 설치가 실패하고 화면에 이유가 안 나온다**
(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`은 logcat에만 있다).
🔴 **③을 직접 깎는다.** 테스터에게는 "앱이 안 깔린다"로 보이고, 못 깐 사람은 **연속 14일
카운트에서 빠진다**(4-4).

🔵 **재현했다 (2026-09-11 · 에뮬레이터).** 여기 원래 「**우리 폰으로는 원리상 재현이 안
된다** — 우리는 그 APK를 안 깔았다」라고 적혀 있었다. **그게 틀렸다.** 에뮬레이터에
깔려 있던 빌드가 바로 위 표 첫째 줄의 인증서(`CN=Android Debug` ·
`55b6f562…`)였다 — 즉 **공개된 APK와 같은 서명 주체**다. 그 위에 릴리스 빌드를
깔았더니 그 자리에서 막혔다:

```
adb install app-release.apk
  → INSTALL_FAILED_UPDATE_INCOMPATIBLE
adb uninstall com.catchflower.app && adb install app-release.apk   # 처방 확인
  → Success · apksigner: CN=CatchFlower · 62b672e5…
```

🔴 **「재현이 안 된다」는 문장 자체가 재는 것을 멈추게 했다.** 우리 기기에 무엇이
깔려 있는지 **세지 않고** 「안 깔았다」고 단정한 것이 원인이다 — 설치된 APK의 인증서는
`apksigner verify --print-certs`로 **1초에 잴 수 있었다**.
[[my-instruments-are-wrong-before-the-artifact]] · [[symptomless-ui-defects]]와 같은 층이다.
🔵 **처방(먼저 삭제)이 실제로 듣는다는 것까지 확인됐다** — 아래 안내문은 근거가 있다.
⚠️ 디버그가 `applicationIdSuffix`를 안 쓰는 것은 **일부러 그렇다**(카카오 키해시가
패키지에 묶여 있다). 그래서 이 충돌은 설정으로 못 없앤다.

**테스터에게 보내는 문장 (그대로 쓴다):**

```text
설치는 아래 초대 링크로만 해 주세요.

```

기록이라 내가 지우지 않는다. 🔵 안내문만으로도 막을 수 있다(위 문장).

## 5. 업로드 **뒤에** 반드시 하는 것

🔴 **Play 앱 서명을 쓰면 구글이 우리 AAB를 다시 서명한다.** 그래서 사용자 기기에 깔리는
앱의 서명은 **업로드 키가 아니다** — 3절의 키해시가 아니라 **Console이 알려주는
`앱 서명 키 SHA-1`**이 실제 값이다. 그것도 카카오에 등록해야 한다:

```bash
python3 android/_tools/sha1_to_keyhash.py <Console의 앱 서명 키 SHA-1>
# → 나온 키해시를 카카오 콘솔에 **추가**한다(업로드 키 것도 남겨 둔다)
```

⚠️ 이걸 빼먹으면 **내 기기에서는 지도가 되고 스토어로 받은 사람만 401**이 된다 —
   우리가 재현할 수 없는 종류의 결함이다.

그 다음: 내부 테스트 트랙에 먼저 올려 **스토어로 받은 앱**에서 지도를 눌러 본다.

## 6. 이 체크리스트가 **못 재는 것**

- Console의 정책 설문·데이터 보안 양식·심사 그 자체. 사람이 답하고 사람이 본다.
- **실기기 카메라.** 에뮬레이터는 virtualscene 벽에 걸린 사진으로 파이프라인까지는
  진짜로 태우지만, 실기기 카메라 하드웨어는 아직 한 번도 안 돌았다
  (`구현현황_AOS.md`의 마지막 미검증 항목).
- **프레임 속도.** 에뮬레이터는 SwiftShader라 jank 비율이 무의미하다.
