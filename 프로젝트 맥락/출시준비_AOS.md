## 2. 업로드 직전 순서 (오너 값이 들어온 **다음에** 이 순서로 돈다)

```bash
# ① 오너 값을 넣는다 — 법적 문서 6칸 + local.properties의 CONTACT_EMAIL
#    (문서를 손으로 고친다. 여기는 생성물이 아니다: 법무/*.txt 가 원본이다)

# ② 웹 문서를 굽는다. 빈 칸이 남아 있으면 **아무 파일도 안 쓰고 멈춘다**
python3 법무/build_웹.py
git add docs/legal && git commit && git push        # 푸시가 곧 공개다(GitHub Pages)

# ③ 두 URL이 브라우저로 정말 열리는지 확인한다 — 안 열리면 등록정보 저장이 안 된다
#    https://aaron-hyosan.github.io/catchflower/legal/privacy.html
#    https://aaron-hyosan.github.io/catchflower/legal/delete-account.html

# ④ versionCode를 올린다 (같은 값은 Console이 거부한다). 지금 1 → 올릴 때 2
#    android/app/build.gradle.kts

# ⑤ 산출물을 만든다. 🔴 플래그를 주지 않는다 — 빈 칸이 남았으면 여기서 멈춰야 맞다
cd android && ./gradlew clean assembleRelease bundleRelease && cd ..

# ⑥ 올릴 파일 자체를 뜯어서 검사한다 (소스가 아니라 산출물을 본다)
python3 출시/_tools/check_release_artifact.py       # 막는 항목 0개여야 한다
python3 android/_tools/check_16kb_alignment.py android/app/build/outputs/bundle/release/app-release.aab

# ⑦ 지도가 실제로 뜨는지 기기에서 본다 (키해시 등록 뒤에만 초록)
python3 android/_tools/check_kakao_map_auth.py

# ⑧ 스크린샷을 **이 빌드에서** 다시 찍는다
python3 출시/_tools/capture_play_screenshots.py
```

🔴 **`-PcfAllowLegalPlaceholders=true`로 만든 파일은 절대 올리지 않는다.** 스크린샷용
escape hatch이고, 그렇게 만든 AAB는 `{{시행일}}`이 적힌 처방침을 품고 있다. 겉모습·크기·
서명이 정상 빌드와 구분되지 않으므로 **⑥의 검사가 유일한 방어선**이다(그 검사는 패키지
안의 asset을 직접 읽는다).

| 업로드 키 카카오 키해시 | `YrZy5Zej88V5CuuG0jSCsXB1zZA=` | 2절 ⑦ · 아래 5절도 본다 |

### 🔴 권한을 선언하면 하드웨어 기능이 **자동으로 필수**가 된다 (2026-08-17에 찾아 고쳤다)

`aapt2 dump badging`으로 보면 매니페스트에 없는 줄이 나온다:

```
uses-implied-feature: name='android.hardware.camera'
    reason='requested android.permission.CAMERA permission'
uses-implied-feature: name='android.hardware.location'
    reason='requested ACCESS_COARSE_LOCATION, and requested ACCESS_FINE_LOCATION'
```

**암시된 기능은 `required=true`다.** 그래서 매니페스트가 일부러 `camera.any`(앞·뒤 아무
카메라)로 열어 뒀는데도 Play는 **뒷면 카메라와 위치 하드웨어를 가진 기기에만** 앱을 보여
주고 있었다. 위치는 이 앱에서 없어도 되는 것이다(장소명만 안 붙고 화면 03이 안내한다).

🔴 **앱 안에 증상이 0이다.** 빌드·설치·22화면·테스트 전부 초록이고, 손해는 "그 기기의
스토어에서 검색되지 않는다"로만 나타난다 — **내 폰으로는 원리상 못 본다.**
🔵 고침은 매니페스트에 `required="false"`를 **명시**하는 것뿐이다(5줄 · 지우면 다시
자동으로 필수가 된다). 고친 뒤 산출물에서 다시 재니 필수 기능이 **둘**만 남았다.
🔵 검사도 같이 고쳤다 — `check_release_artifact.py`가 이제 **badging으로** 권한 집합과
필수 기능을 본다. 예전 판은 `android.permission.*`만 정규식으로 훑어서
**다른 네임스페이스의 권한(`…gms.permission.AD_ID`)이 보이지 않았고** 암시된 기능은
아예 안 봤다. 고친 검사를 **고치기 전 산출물**에 돌려 빨간 줄 2개를 먼저 확인했다.

⚠️ **폭이 6.2MB뿐이다.** 밀도 분할이 거의 아무것도 줄이지 않는다(밀도 차 0.4MB · ABI 차
6.4MB) — 크기의 대부분은 **밀도로 안 갈리는 asset**(일러스트 2,044장)이다. 나중에 줄일
일이 생기면 손댈 곳은 리소스가 아니라 asset이다.

지금 설정이 7행이고, 주소가 들어오면 8행이 된다. 결함이 아니다.

⚠️ 개인 메일을 넣으면 **스토어에 그 주소가 공개된다.**

### 4-4. Play 계정 유형 (F-1) — 🔵 **오너가 정했다: 사업자(조직)** (2026-08-19)

개인 계정이면 **클로즈드 테스트 12명 × 14일**이 프로덕션보다 먼저다. 그 기간에는
프로덕션 출시 버튼이 아예 없다. **사업자(조직)는 면제**이고, 오너가 그쪽을 골랐다
("나는 일단 사업자부터 낼 테니까").

남은 것은 오너가 밟는 순서다 — **사업자등록 → D-U-N-S 신청 → 조직 계정 생성.**
🔴 **D-U-N-S가 임계 경로다.** 구글 안내가 "신규 발급에 **최대 30일**"이라고 못 박아
두었으므로(무료), **사업자등록증이 나오는 날 바로 신청하는 것이 가장 싸다.**
⚠️ 조직 계정은 **D-U-N-S에 등록된 사업체명·주소를 검증에 쓰고 그 이름이 스토어에
나간다** → `사업자등록_위치기반서비스신고.md` 2절(집 주소로 등록하면 집 주소가 공개된다).

## 5. 업로드 **뒤에** 반드시 하는 것

🔴 **Play 앱 서명을 쓰면 구글이 우리 AAB를 다시 서명한다.** 그래서 사용자 기기에 깔리는
앱의 서명은 **업로드 키가 아니다** — 3절의 키해시가 아니라 **Console이 알려주는
`앱 서명 키 SHA-1`**이 실제 값이다. 그것도 카카오에 등록해야 한다:

```bash
python3 android/_tools/sha1_to_keyhash.py <Console의 앱 서명 키 SHA-1>
# → 나온 키해시를 카카오 콘솔에 **추가**한다(업로드 키 것도 남겨 둔다)
```

⚠️ 이걸 빼먹으면 **내 기기에서는 지도가 되고 스토어로 받은 사람만 401**이 된다 —
   우리가 재현할 수 없는 종류의 결함이다.

그 다음: 내부 테스트 트랙에 먼저 올려 **스토어로 받은 앱**에서 지도를 눌러 본다.

## 6. 이 체크리스트가 **못 재는 것**

- Console의 정책 설문·데이터 보안 양식·심사 그 자체. 사람이 답하고 사람이 본다.
- **실기기 카메라.** 에뮬레이터는 virtualscene 벽에 걸린 사진으로 파이프라인까지는
  진짜로 태우지만, 실기기 카메라 하드웨어는 아직 한 번도 안 돌았다
  (`구현현황_AOS.md`의 마지막 미검증 항목).
- **프레임 속도.** 에뮬레이터는 SwiftShader라 jank 비율이 무의미하다.
- 스토어로 받은 앱에서의 카카오 인증(5절). 업로드 전에는 원리상 못 잰다.
- **실제 기기 카탈로그 수.** 필수 기능이 무엇인지는 산출물에서 재지만, 그것이 몇 대의
  기기를 남기는지는 **Console의 `기기 카탈로그`에서만** 보인다(업로드 뒤).
