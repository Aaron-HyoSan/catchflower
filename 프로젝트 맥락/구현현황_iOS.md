# iOS 구현 현황 — 무엇이 되고 무엇이 안 되나

**기준일 2026-08-05 (4차 갱신)** · 코드 실측(`ios/CatchFlower` 42파일 5,488줄) · 단위 53 / UI 30 통과

이 문서는 **안 된 것을 찾기 위한 문서**다. 된 것은 짧게, 안 된 것은 이유까지 적는다.
`진행.md`가 시간순 기록이고, 이 문서는 **지금 시점의 단면**이다. 갱신 시 둘 다 본다.

> **3차 대비 바뀐 것:** 화면 03 권한안내 + B-3 어뷰징 가드 ①.
> **오너가 정한 범위(1~6단계)에 미구현이 없다.**
> **여전히 실기기 0회다** — 이제 남은 리스크는 사실상 이것 하나다.

## 1. 구조적 미구현 — 5개 전부 닫혔다

### 1-1. ✅ 저장 (완료)

`DiscoveryStore`(actor · JSON 파일 · `.atomic`) + `PhotoStore`(`Documents/Photos/`).
`AppSession.record`/`updateVisibility`/`delete`가 전부 `persist()`를 부른다.
**앱을 껐다 켜도 도감이 남는다** — UI 테스트가 `terminate()` 후 재실행으로 직접 확인한다.

- **`Caches/`를 쓰지 않는다.** iOS가 임의로 비운다 → 도감 사진이 소리 없이 사라진다.
- **SwiftData를 쓰지 않았다.** `Discovery`가 이미 `Codable`이고 공유계약 snake_case와 1:1이라
  `@Model`로 바꾸면 계약 필드명을 손으로 다시 맞춰야 하고 서버 업로드 시 변환이 한 번 더 든다.
  수천 건에 쿼리·마이그레이션이 필요하지 않다. **오프라인 동기화 큐를 만들 때 다시 판단한다.**
- 깨진 파일은 `.corrupt`로 치워 두고 빈 상태로 시작 — 조용히 `[]`를 주면 사용자는 도감이 사라진 걸로 본다.

### 1-2. ✅ 사진 저장 (완료)

`photo_url`에는 **파일명만** 넣는다 — 앱 컨테이너 경로는 재설치·복원 때 바뀐다.
`DiscoveryThumbnail`이 실제 사진을 그리고, 없으면 회색 자리를 둔다.
화면 10·11 사진 스트립과 화면 05 `내 발견 기록`이 하드코딩 아이콘에서 벗어났다.

⚠️ **시뮬레이터에서는 여전히 회색이다.** 픽스처가 빈 `Data()`라 저장할 사진이 없다
(빈 파일을 만들면 `exists`는 true인데 `image`는 nil이어서 판단이 꼬인다 → 아예 저장 안 함).
**실사진으로 확인한 적이 없다** = 4절.

### 1-3. ⚠️ 위치 (코드 완료 · 실측 미완)

`LocationProvider`(`@MainActor @Observable`) + `KakaoPlaceService`(actor).
판별과 **동시에** 돌린다 — 순차면 사용자가 위치를 기다린다.
실패하면 throw가 아니라 **nil**이다: 권한 문구가 `도감 등록은 위치 없이도 할 수 있어요`라고 약속했다.

동 코드와 **구 코드를 둘 다 저장한다** — B-6(10명 미달 시 구로 확대)은 런타임에 동에서 구를 못 만든다.

❌ **장소명이 아직 안 온다.** 카카오 키는 유효하지만 **콘솔에서 카카오맵/로컬 서비스가 꺼져 있다**
(`disabled OPEN_MAP_AND_LOCAL service`). 5절 참고. 켜지면 코드 수정 없이 동작한다.

### 1-4. ✅ 확정 정책 — B-5 · B-3 가드 ① 둘 다 흐름에 붙었다

| 정책 | 상태 |
|---|---|
| B-5 같은 종+같은 장소 하루 1회 | ✅ **`CaptureFlow`가 부른다.** 전용 화면 + UI 테스트 2개(막히는 경로 / 장소 옮기면 되는 경로) |
| B-3 어뷰징 가드 ① 희귀종 추가 사진 | ✅ `GamePolicy.needsExtraPhoto` + 전용 화면 + UI 테스트 4개 |

**둘 다 "상수는 있는데 부르는 곳이 0건"이던 자리다.** 규칙을 숫자로 적어두면
구현한 것처럼 보인다 — 정책 상수는 **호출처를 세야** 구현 여부를 알 수 있다.

가드 ①의 설계 판단:
- **1순위는 통과시킨다.** AI 1순위를 받아들인 건 어뷰징의 모양이 아니다.
- **점수를 조건에 넣지 않았다.** 희귀종은 표본이 적어 점수가 원래 낮다 —
  점수까지 보면 정직한 발견을 더 자주 막는다.
- 면제 표시를 **이탈 3곳에서 전부 지운다.** 남은 면제가 곧 우회 경로다.
  단 `다시 고르기`는 면제를 **주지 않는다.**

⚠️ **이 경로는 그냥 찍어서는 밟을 수 없다.** `귀함`은 200종 중 10종이고
개화기가 2~10월에 몰려 있다 → 픽스처 `찍기 (애매 · 2순위 희귀종)`로 밟는다.
11·12·1월에는 후보에 희귀종이 없어서 개화월 밖 희귀종으로 대체한다.

### 1-5. ✅ 공통 UI 컴포넌트 3종 (완료)

문구는 A 문서 3절 그대로다. **세 컴포넌트 모두 `String`이 아니라 enum을 받는다** —
호출부가 문자열을 넘기게 두면 문구가 코드 곳곳에서 창작된다.
컴파일러가 A 문서를 대신 지킨다. **새 문구는 A 문서에 먼저 추가하고 case를 늘린다.**

- **토스트 7종** (`Toast.swift`) — `나만 보기` / `공유하기` / `공유하지 않기`에 붙었다.
  마지막이 중요하다: 공유를 안 해도 **도감에는 이미 등록됐다.**
  색만으로 오류를 구분하지 않는다(아이콘도 바뀐다) · 20자 넘으면 표시 시간 2.6→4초 ·
  새 토스트가 앞 토스트의 타이머를 취소한다.
- **권한 시트 3종** (`PermissionSheet.swift`) — 카메라만 필수(이탈 불가).
  권한을 거부하면 **설명도 나갈 길도 없는 검은 화면**이었다.
  ⚠️ 위치·연락처 이탈 버튼 문구는 A 문서에 없어서 내가 뒀다 → **오너 검토 대상**.
- **확인 다이얼로그 3종** (`ConfirmDialog.swift`) — 이탈·삭제·공유취소.
  ⚠️ **`confirmationDialog`을 쓰면 안 된다.** 이 런타임에서 **취소 버튼이 렌더링되지 않아**
  나가는 길이 바깥 탭뿐이었다 = 제스처 전용 = 타깃 제약 위반. `alert`으로 확정.
  삭제도 스와이프가 아니라 **눌리는 버튼**이다.

**부수 수정:** 네트워크 오류가 화면 12(`어떤 꽃인지 알 수 없었어요`)로 가고 있었다.
사진 문제가 아닌데 "다시 찍어 주세요"는 거짓말이고, B-11 연속 실패 카운터까지 올랐다.
이제 토스트로 빠지고 카메라로 돌아온다.

## 4. ⚠️ 실기기에서 한 번도 돌려보지 않았다 — 지금 최대 리스크

전부 시뮬레이터다. **이제 시뮬레이터로 더 확인할 수 있는 게 별로 없다.**

- `AVCaptureSession` 실동작 (권한 흐름·플래시·전면/후면 전환)
- `UIImage.downscaledJPEG` 실사진 결과와 소요 시간
- **`PlantNetRecognizer`가 실제로 꽃을 맞히는지** — 시뮬레이터는 빈 픽스처라 실제 호출이 안 된다
- **`LocationProvider` 권한 대화상자** 실동작
- 사진 저장 후 도감 썸네일이 실제 사진으로 보이는지

**컴파일은 확인했다.** arm64 기기 슬라이스로 빌드가 통과한다
(`-destination generic/platform=iOS`, 서명 없이). 즉 `#if !targetEnvironment(simulator)`
안쪽의 실카메라·PlantNet 선택 경로가 **타입 체크는 됐다.** 실행은 안 해봤다 —
이 둘은 다른 문제다.

**서명이 안 된다.** `requires a development team` — 실기기 설치에는
**Apple 개발자 계정(무료 Personal Team도 가능)이 Xcode에 로그인돼 있어야 한다.**
지금 `project.yml`에 `DEVELOPMENT_TEAM`이 없다. 오너 확인 필요 → 5절.

**유료 API 실측 보고 전 금지 규칙**과 무관하다 — PlantNet은 무료 티어이고,
실측이 곧 그 보고다. 다만 호출 횟수는 기록한다.
