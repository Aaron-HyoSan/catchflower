# 기획 — 친구를 데려오는 기능 (초대·바이럴)

> **작성 2026-09-11 · AOS 터미널 · 상태 = 기획(구현 전)**
> 이 문서는 **`디자이너_업무/A_문구·버튼_스펙.md` 4절 16번**(초대 링크 목적지가 미정 ·
> 안내 문구가 지키지 못하는 약속을 한다)을 닫기 위한 기획이다.
> 🔴 **코드·SQL·문구를 아직 하나도 고치지 않았다.** 오너가 10절을 정해 주면 그때 움직인다.

---

## 0. 한 줄

**바이럴 기능은 "없다"가 아니라 "반쯤 있고, 그 반이 화면에서 거짓말을 하고 있다".**
초대 탭·초대 문구·초대 버튼은 이미 도는데 **초대를 받은 사실을 서버가 모른다.**
그래서 화면이 약속한 `링크를 받은 지인이 가입하면 자동으로 연결돼요`가 **일어나지 않는다.**

고침은 새 시스템이 아니라 **초대 코드 한 줄**이다 — 링크에 코드를 실어 보내고, 받은 쪽이
그 코드를 넣으면 **양쪽이 바로 친구가 된다.** 그게 이 문서 전체의 내용이다.

## 1. 지금 있는 것 / 없는 것 (실측 · 2026-09-11)

| | 상태 | 근거 |
|---|---|---|
| 초대 탭 | 🔵 **있다** | `FriendsScreen.kt` `enum class FriendTab { MINE, INVITE }` |
| 초대 문구 | 🔵 **있다** | `ShareText.invite` = `같이 동네 꽃을 모아요 · 캐치플라워\n<url>` |
| 공유 시트 | 🔵 **있다** | `FriendsScreen.kt:132` → 안드로이드 공유 시트(카톡·문자 전부 됨) |
| 링크 목적지 | ⚠️ **Play 스토어 주소** | `AppLinks.playStore(BuildConfig.APPLICATION_ID)` — **출시 전이라 지금은 404** |
| 누가 초대했는지 | 🔴 **없다** | 링크에 파라미터가 없다 · `users`에 컬럼 없다 |
| 설치 출처 추적 | 🔴 **없다** | `installreferrer` 의존성 없음 (검색 결과는 lint 캐시의 maven 색인뿐) |
| 딥링크 | 🔴 **초대용은 없다** | 매니페스트의 딥링크는 `catchflower://auth-callback` **하나** |
| 자동 친구 연결 | 🔴 **없다** | `FriendService.request()`는 `state='pending'`으로 넣고, **받는 쪽만** `accepted`로 옮길 수 있다(C-2 상호 수락) |
| 초대 보상 | 🔴 **없다** | 배지·칭호는 오너가 아직 안 짰다 |
| 초대가 눈에 띄는 자리 | 🔴 **사실상 없다** | 초대 버튼은 화면 19 초대 탭의 `ContactsDeniedFallback` 안 — **친구가 이미 없을 때 들어가야 보인다** |

🔵 **좋은 소식은 절반이 이미 있다는 것이다.** 문구·버튼·공유 시트·친구 테이블·친구 랭킹이
전부 돈다. 없는 것은 **"이 사람은 저 사람이 데려왔다"는 한 줄**이다.

## 2. 🔴 지금 화면이 거짓말을 한다 — 이게 이 기획의 진짜 이유

`FriendsScreen.kt`의 `ContactsDeniedFallback`이 이렇게 보여준다:

```
초대 링크로도 친구가 될 수 있어요
링크를 받은 지인이 가입하면 자동으로 연결돼요     ← 🔴 거짓
[ 초대 링크 보내기 ]
```

두 번째 줄을 지키는 코드가 **한 줄도 없다.** 링크는 파라미터 없는 스토어 주소이고,
받은 사람이 설치해도 서버는 누가 보냈는지 모른다. 실제로 벌어지는 일:

1. 내가 링크를 보낸다
2. 지인이 깔고 가입한다
3. **아무 일도 안 일어난다**
4. 지인은 내 닉네임을 직접 검색해서 요청을 보내야 하고, 나는 그걸 수락해야 한다

⚠️ **테스터 12명이 이 문구를 읽는다.** 「연결이 안 되는데요」가 오면 그건 버그 신고가
아니라 **우리가 안 만든 기능**이다. → [[symptomless-ui-defects]] 계열: 문구가 기능보다
앞서 나가면 결함은 코드가 아니라 **약속**에 있다.

🔵 **이건 내가 방금 찾은 게 아니다.** `A_문구·버튼_스펙.md:1458`(4절 16번)에 **이미 열린
오너 문의로 적혀 있다** — 선택지 ① 출시 ② 랜딩 페이지 ③ 초대 코드 체계, 그리고
「③ 없이는 그 자동 연결이 없다 · **링크 목적지와 그 문구를 같이** 정해야 한다」까지.
이 기획은 그 ③을 구체화한 것이다.

## 3. 🔴 먼저 답 — **바이럴로는 테스터를 못 채운다**

오너 질문: 「테스터는 어플 등록하면서도 모을 수 있다고 하지 않았나?」

**모으는 일은 등록 작업과 동시에 할 수 있다. 그런데 이 기능으로는 못 모은다.** 둘은 다른 얘기다.

| | 사실 | 그래서 |
|---|---|---|
| 병행 가능한가 | 🔵 **그렇다.** 스토어 등록정보·그래픽·IARC·데이터 보안 양식을 채우는 동안 사람을 모아도 된다 | 지금부터 모아라 |
| 14일은 언제 시작되나 | 🔴 **12명이 옵트인을 마친 뒤부터** 연속 14일 | 등록이 끝나도 사람이 없으면 **시계가 안 돈다** |
| 초대 링크로 되나 | 🔴 **안 된다.** 클로즈드 테스트는 Play Console에 **이메일이 등록된 계정만** 설치된다 | 링크를 받은 사람은 스토어에서 「항목을 찾을 수 없음」을 본다 |
| 쉽게 하는 방법 | 🔵 **Google 그룹을 테스터 목록으로 지정**할 수 있다 | 오너가 16명 이메일을 받아 적는 대신 **그룹 참여 링크 하나**를 뿌리면 된다 |
| 중도 이탈 | 🔴 이탈자는 카운트에서 **빠진다** | 12명이 아니라 **15~16명**을 모은다 |

🔵 **결론:** 초대 기능은 **프로덕션 이후에 효과가 있는 것**이고, 테스터 15~16명은 여전히
**오너가 사람에게 직접 부탁하는 일**이다. 근거는 `출시준비_AOS.md` **4-4**.
🔵 다만 이 기획을 지금 해 두는 것은 낭비가 아니다 — **2절의 거짓 문구는 테스터가 첫날 본다.**

## 4. 어떻게 "누가 데려왔는지"를 알 수 있나 — 방식 3개

| | 방식 | 되는 것 | 🔴 안 되는 것 |
|---|---|---|---|
| **A** | **초대 코드** (사람이 읽는 6~8자) | 서버 컬럼 하나 + RPC 하나 · **iOS에서 같은 코드가 그대로 돈다** · 카톡·문자·말·손글씨 전부 됨 | 받은 쪽이 **한 번 입력**해야 한다(한 단계 마찰) |
| **B** | **Play Install Referrer API** | 설치하면 자동으로 붙는다(마찰 0) | 🔴 **안드로이드만** · 새 SDK 의존성 · **스토어 경유만**(APK 직접 전달·클로즈드 테스트에서는 안 붙는다) · 🔴 **처방침이 「광고 식별자·분석 도구가 없다」고 공개돼 있다** |
| **C** | ~~Firebase Dynamic Links~~ | — | 🔴 **서비스가 종료됐다. 제안 자체가 불가.** |

### 🔵 권고 = **A (초대 코드)**

이유 셋:
1. **iOS 터미널이 같은 것을 그대로 쓴다.** 서버 RPC 하나면 두 플랫폼이 끝난다.
   B는 안드로이드 전용이라 iOS에 다시 짜야 하고 그건 공유계약상 협의 대상이다.
2. **클로즈드 테스트에서도 돈다.** B는 스토어 설치 경로에 의존하는데, 지금 우리 배포
   경로가 클로즈드 테스트다 — **정작 지금은 B가 아무것도 못 잰다.**
3. **처방침을 안 건드릴 수 있다** — 4-a 참조.

### 4-a. ⚠️ 공개된 처방침과의 관계 (오너 결정 필요 · 10절 ②)

`docs/legal/privacy.html`(시행일 2026-09-08, **공개돼 있다**)는 이렇게 적혀 있다:

- §2에 수집 항목으로 **`친구 요청·수락 관계`**가 이미 들어 있다
- §1 3) **「전화번호와 연락처는 받지 않습니다. 앱은 연락처 권한 자체를 요청하지 않습니다」**
- 광고 식별자·광고 SDK·분석 도구가 **없다**고 적혀 있다

그래서:
- 🔵 **A안의 「누가 누구를 초대했는지」는 사실상 친구 관계와 같은 성질**이지만, **§2에 그 항목이
  명시돼 있지 않다.** 한 줄 추가가 정직하다(예: `초대 코드와 초대한 사람`).
- 🔴 **B안(Install Referrer)은 「설치 출처」라는 새 성질의 데이터**다. 광고 SDK는 아니지만
  §1 3)·§2·§3 목적을 손봐야 하고, Play **데이터 보안 양식**에도 다시 적어야 한다.
- 🔴 **연락처 초대(주소록 매칭)는 아예 후보에서 뺀다.** 「연락처 권한을 요청하지 않는다」를
  **공개적으로 약속**했다. 이걸 뒤집는 것은 기능 추가가 아니라 **약속 파기**다.
  (참고: `users.phone_hash` 컬럼은 있지만 처방침이 전화번호를 안 받는다고 했으므로 **쓰지 않는다.**)

⚠️ 처방침 수정은 **파일을 고치는 일이 아니라 다시 공개하고 시행일을 새로 잡는 일**이다.
`docs/legal/*.html`은 직접 고치지 않는다(생성물) — `법무/build_웹.py` 경로로만 만든다.

## 5. 설계 (A안)

### 5-1. 서버 — 새 마이그레이션은 **`제안/0014`로 낸다**

⚠️ **공유계약 §6:** DB 스키마는 한쪽만 만든다. iOS가 `0001`~`0009`의 주인이므로
AOS는 **`프로젝트 맥락/제안/0014_제안_초대코드.sql`로 제안**하고 `진행.md`에 알린다.
**내가 직접 마이그레이션 번호를 먹지 않는다.**

스케치(확정 아님):

```sql
-- users 에 세 칸
alter table public.users add column if not exists invite_code    text;
alter table public.users add column if not exists invited_by     uuid references public.users(id) on delete set null;
alter table public.users add column if not exists invite_used_at timestamptz;

create unique index if not exists users_invite_code_key
  on public.users (invite_code) where invite_code is not null;
create index if not exists users_invited_by_idx on public.users (invited_by);
```

🔵 **이 컬럼들은 기본으로 닫혀 있다 — 두 겹으로.**
① `users`의 읽기 정책은 `users_read_self` **하나뿐**이다(자기 행만).
② 남의 프로필을 주는 `public_profiles` 뷰는 **컬럼을 하나씩 적어 놓았다**
   (`id, nickname, region_name, dong_code, gu_code`) — 컬럼을 추가해도 안 새어 나간다.

🔴 **그래서 절대 하지 말 것: `invite_code`를 `public_profiles`에 넣는 것.**
그 뷰는 `security_invoker`를 **일부러 껐다** = RLS를 우회해서 `anon`에게까지 준다.
코드가 거기 들어가면 **아무나 남의 코드를 읽어 그 사람과 자동 친구가 된다.**
→ 검사문을 `제안/0014`에 같이 넣는다(뷰 컬럼 목록에 `invite_code`가 없는 것을 센다).

함수 둘:

| 함수 | 하는 일 |
|---|---|
| `public.my_invite_code()` | 내 코드를 준다. 없으면 **그 자리에서 만들어** 저장하고 준다(게으른 발급) |
| `public.redeem_invite_code(code text)` | 코드를 쓴다. **성공하면 그 자리에서 양방향 `accepted` 친구가 된다** |

둘 다 `security definer` · `set search_path` · **`revoke … from public` + `revoke … from anon` 둘 다**
→ [[revoke-from-public-alone-does-not-lock]] (`from public` 하나로는 안 잠기는 함수가 섞여 있다)
+ `grant … to authenticated, service_role`. 그리고 **잠긴 것을 세는 검사절을 같은 파일에 넣는다.**

### 5-2. 코드 문자 집합 — 🔴 아무 랜덤이나 쓰면 안 된다

- **길이 8자** (6자가 아니다 — 6절 ③ 참조)
- 집합 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (**32자**) — `I O 0 1`을 뺐다. 전화로 읽어 주는
  코드에서 이 넷이 제일 많이 틀린다
- 대소문자 구분 없이 받는다(입력을 `upper()`로 정규화)
- 🔴 **입력 정규화에 공백·하이픈을 없앤다.** 카톡에서 복사하면 뒤에 공백이 붙어 온다

8자 × 32집합 = 약 1.1×10¹² — 6절 ③의 대입 공격을 막는 게 이 길이의 목적이다.

### 5-3. 링크 목적지 — A 4절 16번의 답 (오너 결정 · 10절 ①)

| | 안 | 지금 되나 | 비용 |
|---|---|---|---|
| ①-a | **스토어 주소 + 문구에 코드** (`초대 코드 ABCD2345`) | 🔵 **지금 당장 된다** | 0 |
| ①-b | **GitHub Pages 안내 페이지** (`docs/` 에 한 장 추가 · 코드를 URL에 실어 보여주고 스토어로 안내) | 🔵 된다 — `docs/legal/`이 이미 그 방식으로 공개돼 있다 | 0 · 도메인 불필요 |
| ② | 별도 랜딩 도메인 | ⏸ 도메인 구입·비용 | 오너 몫 |

🔵 **권고 = ①-a로 시작하고, 여유가 생기면 ①-b를 얹는다.**
①-a는 오늘 되고, ①-b는 나중에 **문구를 안 바꾸고** 링크만 갈아 끼울 수 있다.
🔴 그리고 **출시 전에는 링크가 404다** — 그 사실은 문구로 감출 수 없으므로
`ShareText.invite`가 **클로즈드 테스트 기간에는 링크를 아예 빼는지**를 정해야 한다(10절 ③).

### 5-4. 받는 쪽이 코드를 넣는 자리

- 🔵 **화면 19 초대 탭에 `받은 초대 코드 입력` 칸을 둔다.** 새 화면을 안 만든다.
- ⏸ 온보딩(1/2 → 2/2)에 넣는 것이 전환율은 높지만 **와이어프레임·A 문서 변경**이 따라온다.
  → 1차에서는 넣지 않는다. 대신 **가입 직후 한 번 초대 탭으로 안내하는 카드**를 검토한다.
- ⚠️ **코드는 언제든 쓸 수 있게 한다**(가입 N일 이내 제한을 걸지 않는다). 제한을 걸면
  「깔았는데 코드가 안 먹어요」가 되고, 그 증상은 **오류 메시지 하나로만** 보인다.

### 5-5. 🔴 자동 친구가 C-2(상호 수락)를 우회한다 — 설계상 가장 중요한 지점

`FriendService`는 요청을 `pending`으로 넣고 **받는 쪽만** `accepted`로 옮길 수 있다.
그게 C-2이고, `제안/0012`가 방금 그것을 정책으로 조인 상태다.
「자동으로 연결돼요」는 **그 규칙을 건너뛰는 것**이다.

🔵 **건너뛰어도 되는 이유:** 코드를 준 사람은 **자기 손으로 코드를 보낸 사람**이다 —
수락 의사를 이미 표현했다. 코드를 넣은 사람도 자기 손으로 넣었다. **양쪽 동의가 있다.**
닉네임 검색 요청(모르는 사람이 나를 찾는 것)과 성질이 다르다.

🔴 **그래서 조건을 못 지키면 자동 연결을 하지 않는다.** `redeem_invite_code`는
`security definer`로 `accepted` 행을 직접 넣되 **아래를 전부 통과할 때만** 넣는다(6절).
⚠️ **그리고 `insert`를 앱에서 하지 않는다.** 앱이 `accepted`를 직접 쓸 수 있게 정책을
열면 **닉네임 검색으로도 무단 친구 등록이 가능해진다** — 그건 `0012`가 막은 바로 그 구멍이다.
→ **정책은 그대로 두고, 함수 안에서만 넣는다.**

### 5-6. ⚠️ 친구 행이 **두 줄** 생길 수 있다

`friendships`의 기본키는 `(requester_id, addressee_id)`다 — **A→B와 B→A가 둘 다 들어갈 수 있다.**
`are_friends`는 `exists`라서 영향이 없지만, **`friend_ranking`이 조인하면 친구가 두 번 나온다.**

🔵 그래서 `redeem_invite_code`는 넣기 전에 **두 방향을 다 본다.**
- 이미 `accepted`가 어느 방향에든 있으면 → 넣지 않고 `이미 친구예요`
- `pending`이 어느 방향에든 있으면 → **새로 넣지 말고 그 행을 `accepted`로 바꾼다**
- 없으면 → 한 방향만 넣는다(초대한 사람을 `requester`로)

→ [[matjip-pipeline-silent-joins]] 계열: 조인이 조용히 두 배가 되면 오류가 0건이고 결과만 틀린다.
**검사절에서 `friend_ranking` 결과 개수를 세는 것으로 잡는다.**

## 6. 어뷰징·안전 — 통과해야 하는 조건

`redeem_invite_code`가 거절하는 경우, 전부:

| | 조건 | 왜 |
|---|---|---|
| ① | **자기 코드는 못 쓴다** | 안 막으면 자기랑 친구가 되고 친구 랭킹에 내가 두 번 나온다(`friendships_no_self`가 DB에서 막지만 오류가 그대로 올라온다) |
| ② | **한 사람은 코드를 딱 한 번만 쓴다** (`invite_used_at`이 있으면 거절) | 안 막으면 한 계정으로 모두와 친구가 된다 |
| ③ | 🔴 **시도 횟수를 센다** | 8자 코드를 무작위로 넣는 대입 공격. **성공하면 남의 사진·좌표를 보게 된다**(`공개범위 = 친구`) — 그래서 실패도 기록하고 **계정당 하루 10회**로 끊는다 |
| ④ | **차단 관계면 거절** (`is_blocked_between`) | 차단한 상대와 코드로 다시 친구가 되면 차단이 뚫린다 |
| ⑤ | **탈퇴한 계정(`deleted_at`)의 코드는 거절** | |
| ⑥ | 실패 이유를 **뭉갠다** | 「없는 코드」와 「이미 친구」를 갈라 주면 ③의 대입 공격에 **존재 여부를 알려주는 오라클**이 된다. 사용자에게는 `코드를 다시 확인해 주세요` 하나로 준다 |

🔴 **③이 이 기획에서 유일하게 새로 만드는 방어다.** 6자 코드에 시도 제한이 없으면
「친구 초대」가 **남의 기록을 여는 열쇠 뽑기**가 된다. 8자 + 하루 10회를 같이 걸어야 한다.

### 6-a. ⚠️ 이미 돌아간 `제안/0011`을 다시 만들어야 한다

`0011` 2절 `purge_deleted_accounts`는 탈퇴 시 `nickname`·`region_name`·`dong_code`·
`gu_code`·`region_changed_at`·`phone_hash`·`age_confirmed_at`을 비운다.
🔴 **컬럼이 셋 늘어나면 그 목록에 `invite_code`·`invited_by`·`invite_used_at`을 더해야 한다.**
안 더하면 탈퇴한 뒤에도 **누가 누구를 데려왔는지가 남는다.**
→ `0011`은 **이미 실서버에서 돌았다.** 함수를 `create or replace`로 다시 올리는 절을
`제안/0014`에 같이 넣는다. **잊으면 증상이 0이다.**

## 7. 초대가 눈에 띄는 자리 (루프 트리거)

🔴 **지금 초대 버튼은 사실상 숨어 있다** — 화면 19 초대 탭의 `ContactsDeniedFallback` 안이다.
바이럴은 기능이 아니라 **자랑하고 싶은 순간에 버튼이 있느냐**의 문제다.

| | 자리 | 왜 여기 | 새 문구 |
|---|---|---|---|
| ⓐ | **친구 랭킹이 비었을 때** (화면 18) | 「나 혼자 1등」이 초대 동기가 가장 센 순간 | 필요 |
| ⓑ | **시즌 결과** (화면 21) | `결과 공유하기`가 **이미 있다** — 여기에 초대 코드를 같이 실으면 새 버튼이 필요 없다 | 문구만 |
| ⓒ | **최초 발견 직후** | 가장 자랑하고 싶은 순간. `ShareText.flower`가 이미 있다 | 필요 |
| ⓓ | 화면 19 초대 탭 (지금 자리) | 유지 | 🔴 **거짓 문구를 고친다** |

🔵 **ⓑ가 가장 값이 싸다** — 공유 버튼이 이미 있고 `ShareText.seasonResult`가 이미 있다.
⚠️ **ⓐⓑⓒ 전부 새 문구다.** `A_문구·버튼_스펙.md`에 **먼저** 적고 그 다음에 코드를 만진다.
🔴 그리고 ⓒ는 **넣을지 자체가 결정 사항이다** — 발견마다 공유를 권하면 성가시다.
1차는 **ⓐ + ⓓ**만 하고 ⓑⓒ는 다음으로 미루는 것을 권고한다.

## 8. 보상 — 🔴 지금 줄 수 있는 것이 거의 없다

오너가 「4시즌 및 배지·칭호는 아직 내가 못 짰다」고 했다. 그래서 **배지·칭호를 보상으로 쓸 수 없다.**
없는 경제를 지금 만들면 나중에 시즌 설계와 충돌한다.

🔵 **1차 보상 = 새 시스템 없이 되는 두 개만.**

| | 보상 | 비용 |
|---|---|---|
| ① | **자동으로 친구가 된다** | 0 — 이게 원래 화면이 약속한 것이고, 친구가 되면 서로 기록·랭킹이 보인다 = **그 자체가 보상** |
| ② | **`함께 시작한 친구 N명`** 을 마이 화면에 보여준다 | `invited_by` 세기 하나 |

🔴 **하지 않는 것:** 아이템·포인트·확률 보상·초대 랭킹.
③ 초대 수 랭킹은 **어뷰징을 부르고**(6절 ③) 시즌 설계와 겹친다. 오너가 시즌·배지를 짠 **뒤에**
「초대 배지」를 얹는 게 순서다.

## 9. 측정 — 🔴 분석 도구가 없다. 그래도 잴 수 있다

처방침에 **「분석 도구나 크래시 수집 도구를 따로 붙이지 않았습니다」**라고 공개했다.
그래서 퍼널을 SDK로 못 잰다. 🔵 **그런데 A안은 서버 컬럼이라 SQL로 세어진다:**

```
발급된 코드 수      = count(invite_code is not null)
쓰인 코드 수        = count(invited_by is not null)
초대로 생긴 친구 수 = 위와 같다(1:1)
K ≈ 쓰인 코드 수 / 코드를 발급받은 사람 수
```

🔴 **못 재는 것을 적어 둔다:** 링크를 몇 명이 **열었는지**, 스토어까지 갔는지, 깔고
코드를 **안 넣었는지**는 원리상 모른다. ①-b(안내 페이지)를 만들면 열람은 재지지만
그건 새 수집 항목이라 처방침이 걸린다.
→ **「깔았는데 코드를 안 넣은 사람」이 이 설계의 사각지대**다. 그게 A안 마찰의 대가다.
→ [[accuracy-metric-is-not-user-outcome]]: 발급 수가 늘어도 친구가 안 늘 수 있다. **쓰인 수만 본다.**

## 10. 🔴 오너가 정해야 하는 것 (이게 A 4절 16번이다)

| | 물음 | 내 권고 |
|---|---|---|
| ① | **초대 링크 목적지** | **①-a 스토어 주소 + 문구에 코드** (오늘 됨 · 비용 0 · 나중에 안내 페이지로 교체 가능) |
| ② | **처방침 §2에 `초대 코드와 초대한 사람`을 넣고 다시 공개할 것인가** | **넣는다.** 안 넣으면 「적어 놓지 않은 것을 수집」이다. ⚠️ 다시 공개 + 시행일 변경 + **Play 데이터 보안 양식**도 같이 |
| ③ | **클로즈드 테스트 기간에 초대 문구를 어떻게 할 것인가** | 🔴 링크가 404다. **테스트 기간에는 초대 탭을 숨기거나** 문구를 `출시 후에 열려요`로 바꾼다 — 셋 중 하나를 골라야 하고 **지금 상태(404 링크를 보낸다)가 최악**이다 |
| ④ | **자동 친구가 C-2를 건너뛰어도 되는가** | **된다**(5-5의 근거). 반대라면 대안은 「초대 코드를 쓰면 **요청이 자동으로 보내진다**」이고, 그때는 문구를 `지인이 가입하면 친구 요청이 자동으로 가요`로 고친다 |
| ⑤ | **초대 보상** | 1차는 **자동 친구 + 숫자만**(8절). 배지는 시즌 설계 뒤 |
| ⑥ | **1차 노출 자리** | **ⓐ 친구 랭킹 빈 화면 + ⓓ 초대 탭**만. ⓑⓒ는 다음 |

⚠️ **①과 ③은 문구와 묶여 있어서 따로 못 정한다** — A 문서 16번이 이미 그렇게 경고한다.
