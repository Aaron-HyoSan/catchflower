## 9. 🔴 AOS가 알린 것 ② — **서버 함수 권한이 안 걸려 있었다** (2026-08-16 · 진행 (79))

**iOS 코드는 안 바뀐다. 그런데 iOS가 알아야 하고, `migrations/`는 iOS 몫이라 iOS가 닫는다.**

실서버 실측(공개 키 · **세션 없음**) — 전부 **200**이 왔다. 기대는 403이었다:

```
dong_member_count → 200 0        region_ranking    → 200 []
friend_ranking    → 200 []       my_season_summary → 200 [{species_count …}]  ← 행을 채워서 준다
```

🔵 **`[]`가 아니라 `200`이 증거다.** 막혀 있으면 `403 / 42501`이고, 200은 **함수가
돌았다**는 뜻이다. 값이 비었는지는 그 계정에 기록이 있느냐일 뿐이다.

**원인은 `0002`·`0004`가 쓴 한 단어다:**

```sql
grant  execute on function public.region_ranking(...) to authenticated;
revoke execute on function public.region_ranking(...) from anon;   -- ← 헛돈다
```

🔴 **함수를 만들면 Postgres가 `PUBLIC`에게 EXECUTE를 자동으로 준다.** `anon`이 그 안에
있으므로 **직접 준 적 없는 권한을 회수해도** PUBLIC 경로가 남는다. `revoke … from anon`은
**오류도 경고도 없이 성공하고 아무것도 바꾸지 않는다.** → **`from public`**이어야 한다.

🔵 **원인과 고침을 로컬 Postgres로 확인했다** — `python3 supabase/_tools/measure_0010_grants.py`
(`pgserver`+`psycopg` · Docker 불필요 · 프로덕션 안 건드린다):

```
① grant authenticated + revoke anon → anon=True  · anon이 실제로 호출 → 🔴 돌았다
② + revoke from public              → anon=False · permission denied
                                     authenticated·service_role → 돌았다
판정: PASS
```

🔴 **카탈로그(`has_function_privilege`)만 보지 않고 `set role`로 실제 호출까지 한다.**
권한은 실행 시점에 걸려서, 카탈로그만 읽으면 "막혔다고 **적혀 있다**"와 "막힌다"를
구분할 수 없다 — 0001 7-3절에서 정책을 그렇게 믿었다가 세 곳이 뚫려 있었다.

⚠️ **앞으로 쓰는 마이그레이션에서 `revoke … from anon`을 쓰지 않는다.** 그 줄은
"잠갔다"고 읽히면서 아무 일도 하지 않는다. `has_function_privilege('anon', …)`으로
**재는 줄을 같은 파일에** 둔다.

| iOS가 할 일 | |
|---|---|
| 🔴 **`제안/0010_제안_함수권한_잠금.sql`을 검토하고 `migrations/0010`으로 승격** | 계약 6절대로 AOS는 `제안/`에만 뒀다(합본 빌더가 오너 승인 없이 서버에 올린다). 오너가 붙여넣는 것은 이미 요청해 뒀다 — **저장소만 뒤처지는 상태**가 (72)에서 한 번 있었다 |
| ⚠️ 앱 코드 변경 **0줄** | 익명 세션의 롤은 `anon`이 아니라 `authenticated`다. 잠가도 **비로그인 열람은 그대로 돈다** |
| ⏸ 못 잰 것 | `delete_comment`·`discovery_reactions`·`assert_self`도 같은 이유로 열려 있을 것이나 **재지 않았다**(프로덕션을 더 찔러 보는 것을 멈췄다). 2절은 같이 잠근다 |

🔴 **위험한 것은 조합이다.** `0001` 7-2절이 `public_profiles`(id·nickname)를 anon에게
**일부러** 열었다. 각각은 결정된 값인데 붙이면 **앱에 든 공개 키만으로 uuid를 얻어
그 사람의 시즌 요약·친구 랭킹을 읽는** 경로가 된다. 무엇을 바꿀지는 iOS가 정한다 —
`public_profiles`를 좁히는 쪽도 선택지다.

🔵 **덧붙여: `0004`~`0009`는 서버에 다 들어가 있다**(같은 실측 — `flowers` **2,057종** ·
`dong_member_count` 200). 문서 세 곳이 "`0004` 미적용"으로 낡아 있었다.
`PGRST202`는 **함수가 없을 때와 인자 이름이 틀렸을 때 똑같이** 온다 — 그것 때문에
1주일 동안 틀린 근거를 들고 있었다.

## 10. 🔴 AOS가 알린 것 ③ — **로그인 게이트 0회 목록에 두 개가 늘었다** (2026-08-16 · 진행 (81))

**공유계약 3절이 바뀌었다. iOS도 같은 두 값을 넣어야 한다** — 한쪽만 막으면
"아이폰에서는 로그인 없이 되던데"가 된다.

| 행동 | 비로그인 | 오너 |
|---|---|---|
| **친구 요청**(닉네임 검색 · 남의 기록 작성자 줄) | ❌ **0회** | 결정 2026-08-16 |
| **닉네임 변경**(프로필 수정) | ❌ **0회** | 결정 2026-08-16 |
| 지역 선택·재변경 | ✅ 제한 없음 | **일부러 안 막는다** (아래) |

**어떻게 발견됐나:** 오너가 실기기에서 눌러 봤다 —
`이거지금 마이프로필이나 설정을 바꿀때면 로그인이 없어도되네?`

🔴 **원인은 판정이 아니라 "행동이 목록에 없었던 것"이다.** AOS는
`GatedAction` enum + `else` 없는 `when`으로 "새 행동이 생기면 컴파일이 깨진다"를
믿고 있었는데, **enum에 넣지 않은 행동은 그 검사를 아예 지나가지 않는다.**
값 목록 검사·grep·테스트 전부 초록이었고 **화면에 증상도 없다**(막혀야 할 것이 그냥 된다).

⚠️ **iOS에서 같은 형태로 반복될 조건이 그대로 있다.** Swift `switch`도 **열거형에 들어온
뒤부터** 지킨다. → 판정 열거형에 **`친구 요청`·`닉네임 변경`을 넣고**, `구현현황_iOS.md`에
**"서버에 쓰는 새 자리를 만들 때마다 이 표를 본다"**를 규칙으로 적는 것을 권한다.

⚠️ **익명 계정에도 이름이 있다.** 서버 트리거 `handle_new_user()`가
`'꽃친구' || substr(new.id::text,1,4)`를 `users.nickname`(not null)에 넣는다 →
프로필 수정 화면이 열 수 있다고 판단하고 **PATCH가 RLS를 통과해 성공한다.**
"익명이니 서버가 거절할 것"이라는 가정으로 막힌 것으로 읽으면 안 된다.

⏸ **지역은 왜 안 막나.** 온보딩이 **로그인 전에** `users.dong_code`를 쓴다 —
막으면 **첫 실행이 진행되지 않는다.** 알려진 손해를 적어 두고 남긴다:
익명으로 바꾸면 `users.region_changed_at`(6개월 규칙)이 소진되고,
연결(`user/identities/authorize`)은 uuid를 유지하므로 **로그인해도 물려받는다.**

**붙일 때 같이 지킬 것 (AOS가 실기기 확인까지 한 판단이다):**

| | |
|---|---|
| 🔴 막혔을 때 **실패 콜백을 부르지 않는다** | `실패`로 부르면 화면이 `연결이 불안정해요`를 띄워 **로그인 문제를 네트워크 문제로 말한다** |
| 🔴 **버튼을 숨기지 않는다** | 안 그리면 왜 못 하는지 화면에 안 적힌다 → 죽은 버튼. 눌리게 두고 **시트로 이유를 말한다** |
| 🔴 **저장 시점이 아니라 버튼에서** 판정한다 | 저장에서 막으면 **다 쓴 이름을 버리게 된다** |
| ⚠️ 남의 기록 화면은 **판정 주인이 둘**일 수 있다 | AOS 화면 16은 시트를 **두 개** 그린다(반응 · 친구 요청). 한쪽만 두면 그 화면에서만 아무 일도 안 하는 버튼이 생긴다 |

⚠️ **서버·RLS·마이그레이션은 한 줄도 안 바꿨다** — 익명 세션을 없애면 열람이 죽는다(9절과 같은 전제).
