## 2. 환경 (설치 완료 · 검증됨)

| | 버전 |
|---|---|
| macOS | 26.5.1 · arm64 |
| **Xcode** | **26.6** (17F113) |
| **Swift** | **6.3.3** |
| 시뮬레이터 | **iOS 26.5** (`iPhone 17`) |
| 최소 지원 타깃 | **iOS 17** — **오너 결정.** E-2 권고(iOS 16)에서 오너가 올렸다 |

**사까마까 유산 규칙을 그대로 따른다** (다른 프로젝트에서 확인된 것):

- **`project.yml`(XcodeGen)이 원본이다. `.xcodeproj`를 직접 수정하지 않는다**
  → 파일을 추가했으면 `cd ios && xcodegen generate`. 안 하면 새 파일이 빌드에 없다.
- **API 키는 소스에 넣지 않는다. 빌드 시점에 주입한다**

빌드·테스트:
```
cd ios && xcodegen generate
xcodebuild test -project CatchFlower.xcodeproj -scheme CatchFlower \
  -destination 'platform=iOS Simulator,name=iPhone 17'
```

## 3. 1~6단계는 끝났다 — 다음 순번

| 단계 | 상태 |
|---|---|
| 1 골격 · 2 모델·`GamePolicy` · 3 CSV 200종 | ✅ |
| 4 도감 04·05·06·22 | ✅ |
| 5 Mock + 저장·사진·위치 | ✅ · `PlantNetRecognizer` 실호출 검증 · **정확도는 하·중만 측정됨(77%)** |
| 6 촬영~판별 07~13 + 권한안내 03 | ✅ (B-5 · B-11 · B-3 가드 ① 포함) |
| 7 랭킹·친구·마이 17~21 | ❌ **서버 없이는 껍데기** — 더미로만 가능 |
| 8 로그인 01·02 | ❌ **provider 토글 + 스키마 대기** (URL·키는 받았다) |

**다음 순번은 `구현현황_iOS.md` 6절이 원본이다.** 지금 1순위는 **오너 답변 B-4**
(유사종 통합)다 — 실측이 이걸 취향에서 **위험 제거 수단**으로 바꿨다.
그 다음이 B-3-a·B-3-b(임계값 두 개). 근거는 셋 다 올려 뒀다.

⚠️ **합격선을 숫자만 보고 비교하지 마라.** 합격선 70%에는 **"난이도 '상' 51종 기준"**
이라는 표본 조건이 붙어 있는데, 내가 (19)에서 그걸 빼고 77%와 비교해
"합격선 통과"로 보고했다. **틀린 보고였고 (21) 3절에서 정정했다.**
**기준에 표본 정의가 붙어 있으면 그것도 같이 만족해야 한다.**

⚠️ **정책 상수를 보면 호출처를 세라.** B-5와 B-3 가드 ①이 각각
"`GamePolicy`에 숫자는 있는데 부르는 곳이 0건"인 채로 오래 있었다 —
**정의는 구현이 아니고, 숫자가 적혀 있으면 구현된 것처럼 보인다.**

⚠️ **"실기기 없이는 못 한다"는 판단을 다시 의심하라.** 4차까지 판별 검증을
실기기 대기로 미뤄 뒀는데, 실제로 막고 있던 건 **픽스처가 빈 `Data()`**였다.
사진 3장을 번들에 넣자 시뮬레이터에서 실엔진이 돌았고 **거기서 버그가 나왔다**
(학명 색인이 정답을 버리고 있었다 · 진행.md (19)).
**측정 스크립트로 대체할 수 있는지 먼저 본다** — `ios/Tools/plantnet_measure.py`가 그 예다.

## 4. iOS만의 이점 하나 — 이걸 꼭 쓴다

**Vision 프레임워크로 "이 사진에 꽃이 있나"를 공짜로 판별한다.**
비용 검토 4절의 **호출 절감 48%**가 이걸 전제로 계산돼 있다.
꽃이 아니면 **API를 아예 부르지 않는다** (신발·하늘 사진이 20% 들어온다고 봤다).

**Android에는 이게 없어서 확인 중이다** (공유계약 5절). iOS는 확실히 된다.

## 5. 하지 말 것

| | 이유 |
|---|---|
| **공유계약 문서의 필드명·enum을 혼자 바꾸기** | Android와 갈라진다 |
| **`꽃도감/꽃목록_200종.csv` 직접 수정** | **생성물이다.** 원본은 `꽃도감/_tools/flowers.py` |

| **기획서 docx에 `patch_docx.py` 재적용** | **멱등이 아니다.** 원본백업에서 복원 후 적용 |
| **문구를 새로 창작** | A 문서에 이미 있다. 없으면 A에 추가하고 기록 |
| **개화기 `"3~4월"` 문자열을 클라이언트에서 파싱** | 서버/적재에서 한 번만 한다 (공유계약 1-2) |
| **DB 스키마를 양쪽에서 만들기** | 먼저 도달한 세션이 만든다 |
| **유료 API 호출** | 실측 보고 전 금지 (오너 규칙) |

| 문구 검토 3건 | B-5 하루 중복 · 권한 시트 이탈 · B-3 가드 ① (전부 A 문서 3절에 초안) |

**B-3-a·B-3-b는 근거가 다 올라가 있다.** 숫자 두 개만 정해지면 코드는 한 줄씩이고,
**Android와 같은 값이어야 하므로 혼자 바꾸지 않았다**(공유계약).

⚠️ **실기기 0회를 "시뮬레이터에서 됨"으로 말하지 않는다** — 단, 이제 범위를 갈라서
말할 수 있다. **판별(응답 파싱·개화월 필터·학명 색인·화면 분기)은 실호출로 검증됐고,
카메라·압축·위치 권한·썸네일은 여전히 0회다.** 뭉뚱그리면 양쪽 다 틀린 말이 된다.
