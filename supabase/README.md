## 검증 — 실제 Postgres에 돌려 봤다

```
pip3 install pgserver "psycopg[binary]"
python3 supabase/test_schema.py     # 71개 통과
```

로컬에 Postgres를 띄워 마이그레이션을 그대로 실행하고 **동작을 확인한다.** Supabase 부분(`auth.uid()`·`auth.users`·`anon`/`authenticated`)만 흉내 낸다.

**이게 왜 있는가.** `create policy`가 붙었다는 것과 **남의 기록이 실제로 안 보인다**는 것은 다른 말이다. 이 프로젝트에서 이미 겪었다 — `GamePolicy`에 숫자만 있고 부르는 곳이 0건이었다. **정의는 구현이 아니다.**

실제로 테스트가 **버그 3종을 잡았다** (전부 "정책은 있는데 안 도는" 모양이었다):

| 버그 | 증상 | 원인 |
|---|---|---|
| **하루 경계가 UTC였다** | 오전 9시 이전 사진이 **전날 기록**이 된다. 아침 산책이 어제로 잡히고 B-5가 엉뚱하게 걸린다 | `captured_at::date`는 시간대 의존이라 인덱스에 못 쓴다 → `captured_date` 컬럼 + 트리거로 한국 날짜를 박는다 |
| **신고 3회 자동 숨김이 안 돌았다** | 3명이 신고해도 계속 보인다 | **정책 안의 서브쿼리도 RLS를 탄다.** `reports`를 세는데 내가 넣은 1건만 보여서 `count < 3`이 항상 참이었다 |
| **차단이 한쪽만 걸렸다** | 차단당한 쪽에는 상대 핀이 **계속 보인다** | 같은 원인. `blocks_read_self` 때문에 내가 건 차단만 보였다 |

→ 판정을 `security definer` 함수(`is_report_hidden`·`is_blocked_between`·`are_friends`)로 빼서 고쳤다. 함수는 **세기만** 하고 boolean 하나만 내보낸다 — 누가 신고했는지·차단했는지는 안 나간다.

## 설계에서 판단이 갈렸던 곳

### 1. 랭킹은 `private` 기록도 센다

기획서 8장이 **도감 등록과 지도 공유는 별개**라고 못 박았고, 화면 13에서 "나만 보기"를 고르면 토스트가 *"도감에는 이미 등록됐어요"*라고 말한다. 그래서 랭킹 함수만 RLS를 우회한다(`security definer`).

우회하지 않으면 **지도에 공유를 안 했다는 이유로 도감 점수가 깎인다.** 사용자는 이유를 알 수 없고, 결국 **경쟁하려면 위치를 전체 공개해야 하는 앱**이 된다 — C-6(여행지 기본 하향)과 정면으로 어긋난다.

**대신 내용은 한 줄도 안 나간다.** 반환에 `lat`·`lng`·`photo_url`·`place_name`·`note`가 없다(테스트가 확인한다). 나가는 것은 닉네임·종 수·대표 꽃 이름뿐이고, 셋 다 원래 화면 17·18에 보이는 값이다. **"어디서 찍었는지"는 여전히 못 본다.**

⚠️ `security definer`라 **인자를 믿을 수 없다.** 남의 uuid를 넣으면 남의 친구 목록이 나온다 → `assert_self`가 먼저 막는다.

### 2. 랭킹을 클라이언트에서 세지 않는다

B-6이 "동 단위 10명 미만이면 구 단위로 확장"이라 **조회 결과가 조건에 따라 다른 집합**이 된다. 양쪽이 각자 세면 한쪽이 10명을 9명으로 세는 순간 다른 랭킹이 나온다. 공유계약 1-2(개화기 파싱)와 같은 원리다.

반환에 `scope`(`dong`/`gu`/`none`)를 넣었다 — 화면 17 제목이 "우리 동네"인데 실제로는 구 단위일 수 있어서 **클라이언트가 제목을 못 속이게** 한다.

### 3. B-5를 DB에서도 막는다

iOS `CaptureFlow`가 이미 막지만, **앱을 우회한 요청은 그대로 들어간다.** 부분 유니크 인덱스로 한 번 더 막는다. 좌표가 없는 기록은 제약에서 빠진다 — 실내·GPS 실패를 막으면 안 된다.

### 4. `phone_hash`를 뷰로 가린다

C-3에 따라 전화번호는 해시만 저장한다. 그런데 랭킹·친구 목록에 닉네임이 나와야 해서 `users`를 남이 읽을 필요가 있다 — 그러면 **해시도 읽힌다.** 전화번호는 자리수가 정해져 있어 10자리 전수 대입이 현실적이므로 해시라도 위험하다. → `users`는 본인만 읽고, 남의 닉네임은 `public_profiles` 뷰로만 본다(`phone_hash`가 없다).
