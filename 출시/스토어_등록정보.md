# Play 스토어 등록정보 · 앱 콘텐츠 답안 (원본)

이 파일이 **Play Console에 붙여넣는 모든 문장과 선택지의 원본**이다. 콘솔에서 직접
고치지 말고 여기를 고친 뒤 다시 붙여넣는다 — 콘솔에만 있는 문장은 아무도 다시 못 읽고,
다음 업데이트에서 조용히 낡는다(이 저장소의 "오너가 붙여넣는 문서는 어긋난다").

🔴 **아래 1절의 문장은 기계가 읽는다.** `출시/_tools/store_listing.py`가 제목 줄
(`### 이름 · 최대 N자`)과 바로 다음 코드블록을 짝지어 글자 수를 세고, 스토어 그래픽의
문구도 같은 블록에서 읽는다. 그래서 **제목 줄 형식과 코드블록 위치를 바꾸면 안 된다.**
문구를 그래픽에 다시 적으면 두 벌이 되고, 그림과 스토어 글이 다른 말을 한다.

    python3 출시/_tools/store_listing.py            # 글자 수·빈 칸 검사
    python3 출시/_tools/store_listing.py --print 짧은_설명

⚠️ **채우지 않은 칸이 남아 있으면 검사가 실패한다.** 이 문서에서 두 겹 중괄호로 감싼
자리가 그것이다. 오너에게 받을 값이고
`디자이너_업무/A_문구·버튼_스펙.md` 4절 24번과 같은 목록이다.


## 1. 스토어 등록정보 (앱 > 기본 스토어 등록정보)

### 앱 이름 · 최대 30자

```text
캐치플라워 - 우리 동네 꽃 도감
```

왜 이 이름인가 — 앱 안 이름은 `캐치플라워`뿐이지만, 스토어에서는 그 다섯 글자만으로는
무슨 앱인지 알 수 없다. `꽃`·`도감`이 검색어이고 `우리 동네`가 이 앱과 다른 식물
판별 앱의 차이(동네 단위 순위·지도)를 한 마디로 말한다.
🔴 **순위·최고·1위 같은 말을 넣지 않는다** — Play는 스토어 등록정보의 순위 주장과
프로모션 문구를 이름에 넣는 것을 금지한다(스팸 및 최소 기능 정책).

### 짧은 설명 · 최대 80자

```text
꽃을 찍으면 이름을 찾아 줍니다. 2,044종 도감을 채우고 우리 동네 순위에 이름을 올려 보세요.
```

### 자세한 설명 · 최대 4000자

```text
동네를 걷다 만난 꽃, 이름을 몰라 그냥 지나치지 않았나요?

캐치플라워는 꽃을 사진으로 찍어 도감을 채우는 수집 게임입니다.
꽃 이름을 몰라도 됩니다. 찍으면 후보를 찾아 드리고, 고르면 도감에 한 칸이 채워집니다.

■ 이렇게 놀아요
1. 아래 가운데 '꽃 촬영'을 눌러 눈앞의 꽃을 찍습니다.
2. 지금 피는 꽃 중에서 가장 비슷한 후보를 최대 3개 보여 줍니다.
3. 맞는 것을 고르면 도감에 등록됩니다. 처음 만난 꽃이면 '첫 발견'으로 남습니다.
4. 지도에 공유하면 같은 동네 사람들이 그 꽃을 보러 갈 수 있습니다.

■ 2,044종 도감
- 우리 주변에서 만날 수 있는 꽃 2,044종이 도감에 들어 있습니다.
- 꽃마다 흔함 / 보통 / 귀함이 나뉘어 있어, 도감을 채울수록 남은 칸이 귀해집니다.
- 계절이 지나면 그해에는 못 찍는 꽃이 있습니다. 내년을 기다리는 칸이 도감에 남습니다.

■ 지금 피는 꽃만 후보로
꽃이 피는 달을 알고 있어서, 지금 피지 않는 꽃은 후보에서 빠집니다.
그래서 봄에 가을 국화가 답으로 올라오는 일이 없습니다.

■ 우리 동네 순위 · 친구 순위
- 시즌마다 '이번 시즌에 모은 꽃 수'로 순위를 매깁니다.
- 활동 지역(동)을 정하면 같은 동네 사람들과, 친구를 추가하면 친구들과 겨룹니다.
- 12월부터 2월까지는 쉬는 기간입니다. 다음 시즌이 시작될 때까지 남은 날을 알려 줍니다.

■ 사진은 기기에만 남습니다
촬영한 사진은 서버에 올리지 않습니다. 꽃 이름을 찾는 순간에만 꽃 인식 서비스로
사진 한 장을 보내고 결과만 받아 옵니다. 지도에 공유할 때도 사진이 아니라
꽃 이름과 위치, 한 줄 메모가 올라갑니다.

■ 공개 범위를 매번 고릅니다
발견 기록마다 비공개 / 친구만 / 전체 중에서 고를 수 있고, 나중에 바꿀 수도 있습니다.
다른 이용자의 기록은 신고하거나 그 사람을 차단할 수 있습니다.

■ 필요한 권한
- 카메라: 꽃을 찍는 데 필요합니다. 앨범에 있는 사진은 등록할 수 없습니다.
- 위치(선택): 촬영한 곳을 기록하고 우리 동네를 찾는 데 씁니다.
  허용하지 않아도 촬영·판별·도감은 모두 그대로 쓸 수 있습니다.

■ 걸어 다닐 때는 주변을 먼저 보세요
- 이동하면서 화면을 보지 마세요.
- 남의 집, 출입이 금지된 곳, 위험한 곳에는 들어가지 마세요.
- 꽃은 꺾지 말고 그대로 두고 사진만 가져오세요.
- 판별 결과는 인공지능의 추정입니다. 먹거나 약으로 쓰는 판단에는 절대 쓰지 마세요.

만 14세 이상 이용할 수 있습니다. 이용료가 없고, 앱 안에 광고와 유료 결제가 없습니다.
```

| 항목 | 값 | 근거 |
|---|---|---|
| 앱 또는 게임 | **게임** | 도감·시즌 순위·첫 발견이 핵심 루프다(기획서). 참고한 사례(포켓몬GO)도 게임이다 |
| 카테고리 | **캐주얼** | 한 판이 짧고 규칙이 하나다. 대안은 `어드벤처`인데 전투·스토리가 없어서 안 고른다 |

| 이메일 | `{{문의_이메일}}` | 앱의 `설정 > 고객 문의`와 **같은 주소여야 한다**(`local.properties`의 `CONTACT_EMAIL`) |
| 웹사이트 | `https://aaron-hyosan.github.io/catchflower/` | 문서 목록 페이지 |
| 전화번호 | 비워 둔다 | 필수가 아니다. 적으면 공개된다 |
| 개인정보처리방침 URL | `https://aaron-hyosan.github.io/catchflower/legal/privacy.html` | `python3 법무/build_웹.py` 결과를 커밋·푸시해야 열린다 |

🔴 **카테고리를 `게임`으로 고르면 콘텐츠 등급 설문이 게임용으로 바뀐다**(구매·도박·경쟁
항목이 늘어난다). 4절 답안은 게임용 설문 기준으로 적어 두었다. 나중에 `앱`으로 바꾸면
등급 설문을 다시 작성해야 한다.


## 3. 앱 액세스 권한 (앱 콘텐츠 > 앱 액세스 권한)

🔴 **"모든 기능을 제한 없이 사용할 수 있음"을 고르면 안 된다.** 이 앱은 카카오 로그인
없이도 도감·촬영·판별을 쓸 수 있지만, **판별 2회를 넘기면 로그인을 요구한다**
(비로그인 판별 2회 · 오너 결정 2026-08-14). 심사자는 카카오 계정이 없을 수 있으므로
그대로 두면 **거기서 심사가 멈춘다.**

선택: **일부 기능이 제한됨** → 안내에 아래를 그대로 적는다.

```text
로그인 없이 사용할 수 있는 범위
- 앱을 처음 열면 계정을 만들지 않고 바로 시작합니다.
- 도감 열람, 꽃 촬영, 꽃 판별(2회), 지도 열람은 로그인 없이 됩니다.

로그인이 필요한 지점
- 3번째 판별부터, 그리고 지도 공유 · 댓글 · 좋아요 · 친구 요청 · 닉네임 변경은
  카카오 계정 로그인이 필요합니다.
- 로그인 화면: 마이 탭 > 로그인, 또는 판별 3회째에 자동으로 안내가 뜹니다.

심사용 계정
- 카카오 계정: {{심사용_카카오_아이디}}
- 비밀번호: {{심사용_카카오_비밀번호}}
- 이 계정은 심사용으로만 만든 계정이며 2단계 인증을 걸어 두지 않았습니다.
```

⚠️ **오너 작업이다**(6절 ①). 심사용 카카오 계정을 하나 만들어 위 두 칸을 채운다.
자기 개인 카카오 계정을 넣지 않는다 — 비밀번호가 Play Console에 저장된다.


## 4. 콘텐츠 등급 설문 (IARC)

이메일과 카테고리를 넣으면 문항이 나온다. 아래가 **이 앱의 사실**이다.

| 문항 | 답 | 근거 |
|---|---|---|
| 폭력 (사실적/만화적/성적 폭력) | 없음 | 전투·피해 표현이 없다 |
| 성적 콘텐츠 · 노출 | 없음 | |
| 욕설·비속어 | 없음 (앱이 만드는 문장에는 없다) | 이용자 댓글은 아래 UGC 항목에서 따로 답한다 |
| 약물·주류·담배 | 없음 | |
| 도박 · 시뮬레이션 도박 | 없음 | 확률 뽑기·베팅이 없다 |
| 무서운 장면 | 없음 | |
| **이용자 간 상호작용** | **있음** | 댓글(최대 200자), 좋아요, 친구 요청, 닉네임이 서로 보인다 |
| 상호작용 내용이 조정되는가 | 신고·차단 기능이 있고 운영자가 확인한다 | 이용약관 제9조 4항 · 제10조 |
| **이용자의 위치를 다른 이용자와 공유** | **있음** | 지도 공유 시 촬영 위치가 공개 범위에 따라 보인다 |
| 개인정보를 다른 이용자와 공유 | 닉네임과 활동 지역(동)만 | 이메일·전화번호는 받지 않는다 |
| 디지털 구매 · 앱 내 구매 | **없음** | 결제 SDK가 없다(실측: `build.gradle.kts` 의존성에 billing 없음) |
| 광고 | **없음** | 광고 SDK가 없다(실측: 같은 의존성 목록) |
| 사용자 생성 콘텐츠(UGC)를 공유할 수 있는가 | **예** | 사진은 안 올라가지만 메모·댓글·닉네임이 공개된다 |

예상 결과: 국내 **전체이용가**, ESRB **Everyone**, PEGI **3** + `이용자 상호작용` ·
`위치 공유` 설명자. ⚠️ **결과가 다르게 나오면 위 답을 고치지 말고 그대로 두고 알려 달라** —
등급이 올라가는 것은 문제가 아니고, 사실과 다르게 답하는 것이 정책 위반이다.


## 5. 앱 콘텐츠 나머지 선언

| 선언 | 답 | 비고 |
|---|---|---|
| 광고 포함 | **아니요** | |
| 앱 액세스 권한 | 일부 제한 | 3절 |
| 콘텐츠 등급 | 4절 | |
| **대상 연령층** | **16-17세 · 18세 이상** | 아래 ⚠️ |
| 어린이의 관심을 끌 수 있는 앱인가 | **아니요** | 캐릭터·보상 연출이 있으나 아동을 대상으로 만들지 않았고 마케팅도 성인 대상이다 |
| 뉴스 앱 | 아니요 | |
| 코로나19 접촉 확인·정보 앱 | 아니요 | |
| 데이터 보안 | 6절 | |
| 정부 앱 | 아니요 | |
| 금융 기능 | 없음 | |
| 건강 앱 | **아니요** | 🔴 꽃 판별을 건강·의학 정보로 소개하지 않는다. 이용약관 제6조 2항이 식용·약용 사용을 금지한다 |
| 생성형 AI 앱 | **아니요** | 앱의 AI는 사진을 **분류**한다. 이용자에게 글·그림을 생성해 주지 않는다 |
| 사용자 생성 콘텐츠 | **예** | 신고 기능(앱 안 신고 사유 선택) · 차단 기능 · 이용약관 제8조 금지행위 · 운영자 확인(제9조 4항)을 근거로 적는다 |

⚠️ **대상 연령층에 `13-15세`를 넣지 않는 이유.** 이 앱은 이용약관 제4조에서 **만 14세
이상**만 받는다. 그런데 Play의 선택지는 `9-12` / `13-15` / `16-17` / `18세 이상`뿐이라
**14를 정확히 표현할 방법이 없다.** `13-15`를 고르면 "13세도 받는다"고 선언하는 셈이라
앱 안 고지와 어긋나고, 청소년 대상 추가 정책까지 함께 걸린다. 그래서 **더 좁게**
선언한다. 🔴 그 대가로 **만 14~15세 이용자는 실제로 허용되는데 선언에는 안 들어간다** —
Play가 이 불일치를 물으면 이용약관 제4조가 기준이라고 답한다.


## 6. 데이터 보안 (앱 콘텐츠 > 데이터 보안)

측정으로 채운 답이다. 근거 스크립트를 각 줄에 적었다.

**공통 답**
- 전송 중 데이터를 암호화하는가: **예** (실측: `usesCleartextTraffic="false"`, 모든 호출이 HTTPS)
- 데이터 삭제 요청 방법을 제공하는가: **예** — 앱 안 `설정 > 회원 탈퇴` + 웹
  `https://aaron-hyosan.github.io/catchflower/legal/delete-account.html`
- 독립적인 보안 검토를 받았는가: 아니요
- 가족 정책(아동 대상): 해당 없음

| 데이터 유형 | 수집 | 공유 | 목적 | 필수/선택 | 근거 |
|---|---|---|---|---|---|
| 위치 — 대략적인 위치 | 예 | 아니요 | 앱 기능 | **선택** | 활동 지역 찾기. 권한을 거부해도 앱이 다 돈다 |
| 위치 — 정확한 위치 | 예 | 아니요 | 앱 기능 | **선택** | 발견 기록의 위도·경도 |
| 사진 | 예 | **예** | 앱 기능 | 필수 | 판별하는 순간에만 Pl@ntNet(프랑스)로 1장. 서버에 보관하지 않는다 |
| 개인정보 — 사용자 ID | 예 | 아니요 | 앱 기능 · 계정 관리 | 필수 | 임의 UUID, 닉네임, 카카오 계정 식별자 |
| 앱 활동 — 기타 사용자 생성 콘텐츠 | 예 | 아니요 | 앱 기능 | 필수 | 닉네임, 한 줄 메모(40자), 댓글(200자), 신고 사유 |
| 앱 정보 및 성능 — **진단** | **예** | **예** | **분석** | **필수(끌 수 없다)** | 🔴 아래 ⚠️ |

🔴 **진단 항목을 빼면 안 된다.** 우리가 붙인 분석 도구는 없지만, 기기 안 꽃 여부 판단에
쓰는 **Google ML Kit이 자기 사용 통계를 Google로 보낸다.** 이건 읽어서 안 것이 아니라
기기에서 재서 확인했다:

    python3 android/_tools/measure_mlkit_telemetry.py
    → 판정: ML Kit 원격 측정 흔적 있다
      logcat: Storing event with priority=DEFAULT, name=FIREBASE_ML_SDK for destination cct
      전송지(base64 해독): https://firebaselogging.googleapis.com/v0cc/log/batch
      JobInfoSchedulerService 업로드 job이 이 실행에서 4번 START/STOP

  · 대조군으로 ML Kit이 실제로 돌았음을 같은 실행에서 확인했다(`1차필터: 꽃=false`).
  · 그 판정 때문에 `법무/개인정보_처리방침.txt` 1항 2)와 4항 (4)를 고쳤다.
  · **끄는 설정이 없다** — AAR에 opt-out 플래그가 없다. 그래서 `선택`이 아니라 `필수`다.
  · 공유 `예`: 받는 곳이 우리 서버가 아니라 Google이다.

⚠️ **못 잰 것 — 그 통계에 임의의 설치 식별자가 들어가는지 모른다.** HTTPS라서 본문을
   못 봤고, 플레이스토어 이미지 에뮬레이터는 `adb root`가 막혀 CCT 이벤트 DB도 못 열었다.
   Google이 문서로 밝힌 범위가 진단 정보여서 **진단만 신고한다.** 콘솔의 SDK 색인이
   `기기 또는 기타 ID`를 지목하면 그때 항목을 추가한다(그건 반려가 아니라 경고로 온다).

⚠️ **카카오·Supabase는 `공유`로 신고하지 않는다.** Play의 정의에서 "우리를 대신해
   처리하는 서비스 제공자"에게 넘기는 것은 공유가 아니다(지도 타일 요청·좌표↔주소 변환,
   DB 호스팅). 처방침 4항에는 둘 다 적혀 있다 — 그쪽 기준(개인정보 보호법)은 더 넓다.
