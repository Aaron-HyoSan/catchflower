# 일러스트 납품 규격 — 캐치플라워 꽃 도감

**대상** 2,057종 (`꽃도감/일러스트_파일명_목록.csv` — **줄 수와 파일명이 여기 다 있다**)
**기준** 기존 납품 200장을 **실측한 값**이다(추측이 아니다). 재측정 명령은 5절.

---

## 1. 한 장의 규격

| 항목 | 값 | 왜 이 값인가 |
|---|---|---|
| 크기 | **512 × 512 px** 정사각 | 🔴 코드가 `inSampleSize = 512 / bucket`으로 **512를 가정**한다. 다르면 크기가 조용히 어긋난다 |
| 형식 | **PNG-24 + 알파** (RGBA) | 200장 전부 알파를 실제로 쓰고 있다. 배경 투명이 전제다 |
| 배경 | **완전 투명** | 코드가 `ARGB_8888`을 강제한다 — `RGB_565`로 줄이면 **투명 배경이 검게 칠해진다** |
| 여백 | 네 변에 **그림이 닿지 않게** | 실측: 200장 모두 위·아래 변에 불투명 픽셀 0. 그리드에서 잘려 보인다 |
| 용량 | 장당 **~50KB** (200장 평균 48.5KB · 최대 96KB) | 4절의 총량 문제 |
| 색공간 | sRGB | |

**한 종에 한 장.** 여러 각도·부위 컷은 지금 앱이 못 읽는다.

## 2. 🔴 파일명이 규격의 핵심이다 — 이름이 아니라 **번호**가 키다

```
0034_남산제비꽃.png     ← 4자리 번호 + _ + 아무 이름
```

| 규칙 | |
|---|---|
| **번호가 유일한 키다** | 빌드가 `0034_….png` → `assets/flower_illust/0034.png`로 **번호만 남겨** 복사한다 |
| 번호 뒤 이름은 **사람이 읽기 위한 것** | 오타·띄어쓰기·`복사 2` 같은 접미사가 붙어도 상관없다 (기존 200장은 전부 `0001_개나리 1.png` 꼴이다) |
| 번호는 `일러스트_파일명_목록.csv`의 **`파일명` 칸을 그대로 쓴다** | 이름으로 매칭하지 않는다. 2,057줄에 쓸 파일명이 이미 적혀 있다 |
| **번호 중복은 빌드를 세운다** | `0034_A.png`와 `0034_B.png`가 같이 있으면 어느 쪽이 들어갔는지 알 수 없어서, 조용히 하나가 이기지 않도록 실패시킨다 |

### 🔴 2026-08-11 정정 — 이 문서가 **번호를 못 찾는 파일을 가리키고 있었다**

원래 "번호는 `꽃목록_후보_2000종.csv`의 `도감번호`"라고 적혀 있었다. **그대로 하면
신규 1,857종의 파일명을 만들 수 없다** — 그 파일은 행이 2,057개인데 `도감번호`가
채워진 행은 **200개뿐**이고 나머지는 **빈칸**이다(세어서 확인: `200 / 2057`).

| 파일 | 행 | 도감번호 채워진 행 |
|---|---|---|
| `꽃목록_후보_2000종.csv` | 2,057 | **200** ← 신규종은 빈칸 |
| `꽃목록_확장_2057종.csv` | 2,057 | 2,057 (번호의 원본) |
| **`일러스트_파일명_목록.csv`** | **2,057** | **2,057 · 쓸 파일명까지 적혀 있다** |

**그래서 디자이너가 볼 파일은 `일러스트_파일명_목록.csv` 하나다.** `파일명` 칸을
그대로 쓰면 된다. 이 목록은 손으로 만들면 낡으므로(실제로 `상태` 칸이 낡아 있었다)
**생성기를 뒤늦게 붙였다**:

```
python3 꽃도감/_tools/build_illust_worklist.py           # 다시 만든다
python3 꽃도감/_tools/build_illust_worklist.py --check    # 낡았는지만 본다 (exit 1 = 낡음)
```

`상태` 칸은 **납품 폴더를 실제로 훑어서** 채운다 — 번호로만 판정한다(이름은 NFD/NFC가
갈려서 못 쓴다, 아래). 그래서 그림을 넣고 다시 돌리면 `미납품`이 `납품됨`으로 바뀐다.

### 왜 이름을 키로 안 쓰나 (실측)

**macOS는 파일명의 한글을 NFD(자모 분리)로 저장하고, `flowers.json`의 이름은 NFC다.**
납품된 200장 파일명 **200/200이 NFD**다. 이름으로 찾으면 **200종 전부 못 찾는데
눈으로는 똑같은 글자**라 원인을 찾기 어렵다. 번호만 쓰면 이 문제가 아예 생기지 않는다.

### 번호는 4자리다 (2026-08-11 적용 완료)

3자리(`^(\d{3})_` · `"%03d.png"`)는 **999번까지만** 받았다. 2,057종은 4자리라
코드와 기존 파일을 같이 바꿨다:

- `Flower.illustAssetName` → `flower_illust/%04d.png`
- `SyncSharedAssets` 정규식 → `^(\d{3,4})_` (3자리로 와도 4자리로 정규화해 복사한다)
- 기존 200장 이름 변경 `001_개나리 1.png` → `0001_개나리 1.png`

**디자이너는 4자리로 주면 된다.** 3자리로 와도 빌드가 받아서 4자리로 바꿔 넣는다
(조용히 사라지는 것보다 낫기 때문에 남겨 둔 여유다).

## 3. 넘기는 방법

```
꽃도감/꽃도감_일러스트/       ← 여기에 그냥 넣는다. 하위 폴더 없이 평면으로.
```

- 확장자는 소문자 `.png`
- `.psd`·`.ai` 원본은 이 폴더에 **넣지 않는다** (빌드가 png만 집지만 저장소가 커진다)
- 배치로 나눠 줘도 된다 — 빠진 번호는 그 칸만 비고 앱은 정상 동작한다
  (빌드가 `꽃 일러스트 N장을 복사했다`로 실제 개수를 찍는다)

## 4. 🔴 2,057장은 그대로 담으면 앱이 스토어에 못 올라간다

실측 근거:

| | 장당 | 2,057장 | 결과 |
|---|---|---|---|
| **PNG 원본** (현행) | 48.5 KB | **+97 MB** | 현재 APK 105MB → **약 200MB · Google Play 기본 상한 초과** |
| WebP 무손실 | 27.7 KB | +56 MB | 여전히 부담 |
| **WebP 손실 q90** | **14.9 KB** | **+30 MB** | 현실적 |

> 측정: 납품 12장을 실제로 변환해 잰 값이다.
> 현재 APK 105MB의 대부분은 일러스트가 아니다 — 네이티브 라이브러리 74.7MB · dex 36.9MB ·
> 일러스트 9.5MB. 그래서 **일러스트만 줄여도 부족하고, 일러스트를 안 줄이면 확실히 넘는다.**

**그래서 납품은 PNG로 받는다.** 변환은 내가 빌드 단계에서 한다(원본을 손실 압축으로
받으면 되돌릴 수 없다). 디자이너는 위 1절 규격의 PNG만 주면 된다.

**메모리도 걸린다.** 512×512 RGBA 한 장이 메모리에서 **1.0MB**다. 캐시 상한이 힙의 1/8이라
장수가 늘어도 터지지는 않지만, 그리드 스크롤 성능은 장수와 무관하게 유지된다(디코딩 크기를
셀 크기에 맞춘다).

## 5. 규격 확인 명령 (납품 후 내가 돌린다)

```bash
python3 꽃도감/_tools/verify_illust.py        # 크기·모드·알파·여백·번호중복·NFD를 전부 본다
```

이 검사가 없으면 **규격을 어긋난 장이 그냥 화면에 나온다** — 512가 아닌 장은 크기가
어긋난 채로, 배경이 흰 장은 흰 사각형으로 보인다. 둘 다 예외가 안 난다.
