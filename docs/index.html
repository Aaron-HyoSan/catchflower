02실제 화면

실기는 앱을 실제로 띄워 찍은 화면이다. 설계는 카메라 하드웨어가 필요해 에뮬레이터로 담을 수 없는 구간이라 와이어프레임으로 싣는다.

도감 홈 실기200칸 중 발견한 3칸만 색이 있다. 못 잡은 꽃은 실루엣
도감 상세 실기학명·과·개화기와 내가 찍은 사진이 함께 남는다
지도 실기카카오 벡터 타일 위에 내 발견 핀이 실제로 찍힌다
동네 랭킹 실기서버가 센 순위. 동 인원이 적으면 구로 넓힌다
활동 지역 실기현재 위치를 실제로 역지오코딩해 동을 찾는다
마이 실기모은 꽃·발견 횟수·공유 수. 근거 없는 값은 두지 않았다
꽃 촬영 설계앨범 사진은 등록할 수 없다 — 직접 찍어야 한다
AI 분석중 설계온디바이스 필터 → 개화월 후보 압축 → PlantNet
판별 확인 설계후보를 보여주고 사용자가 고른다. AI를 단정하지 않는다
신규 등록 설계도감 칸이 채워지는 순간
지도 공유 설계공개 범위를 명시적으로 고른다. 기본은 비공개

03어떻게 노는가

촬영 한 번이 도감 · 지도 · 랭킹 세 곳에 동시에 남는다.

  1. 꽃을 찾아 찍는다 (화면 07) 앨범 사진은 안 된다. 걸어 나가서 직접 찍어야 게임이 성립한다
  2. AI가 종을 좁힌다 (화면 08) ① ML Kit이 꽃인지 먼저 본다(온디바이스·무료) → 꽃이 아니면 유료 API를 부르지 않는다(차단율 92.4%) ② 지금 피는 달의 종만 후보로 좁힌다(8월 = 98종) → ③ PlantNet에 보낸다
  3. 후보 중에서 내가 고른다 (화면 09) AI가 단정하지 않는다. 최종 결정은 사람이 한다
  4. 도감 칸이 채워진다 (화면 10 · 11) 처음 잡은 꽃이면 신규 등록, 이미 있으면 재발견으로 횟수가 오른다
  5. 지도에 남길지 고른다 (화면 13) 기본은 비공개다. 공개 범위를 사용자가 직접 정한다
  6. 지도 · 도감 · 랭킹에 반영된다 (화면 14 · 04 · 17) 같은 동네 이웃들과 이번 시즌 수집 종 수로 순위를 겨룬다
계절이 규칙이다. 겨울에 피는 꽃이 6종뿐이라 12~2월은 휴지기로 두고 시즌을 3~8월 / 9~11월로 나눴다. 개화월 하드 필터가 없으면 PlantNet이 11월에 "벚꽃"을 1순위로 준다. 그래서 후보가 0개인 달에는 네트워크를 아예 타지 않는다.

04설계에서 가장 신경 쓴 것

기능을 늘리는 대신 틀렸는지 알 수 있게 만드는 데 시간을 썼다.

1. 유료 API를 함부로 부르지 않는다

온디바이스 필터로 92.4%를 미리 걸러내고, 개화월 후보가 0개면 네트워크를 타지 않는다. 호출 직전에 로그를 남겨 어느 촬영이 과금됐는지 사후에 확인할 수 있다.

근거 · 진행.md (15)(46)

2. AI 점수를 신뢰도로 착각하지 않았다

PlantNet 점수는 4,932종에 퍼진 확률이라 정답도 0.1 근처에 흔히 온다. 실패 임계값을 0.30으로 뒀더니 버려진 4장이 전부 정답이었다(실기기 실측). 0.05로 내려 1순위 정답률 50% → 80%가 됐다.

근거 · 진행.md (43)(44)

3. 실패 화면이 원인을 가리지 않게 했다

어떤 꽃인지 알 수 없었어요는 원인이 세 가지인데(API가 못 알아봄 / 도감·개화월에서 걸림 / 점수 미달) 화면에는 똑같이 보인다. 로그 네 줄로 갈라 두고 그 로그의 내용까지 테스트로 고정했다 — 로그는 조용해져도 증상이 없다.

근거 · 진행.md (46)

4. "테스트가 초록"을 증거로 쓰지 않았다

초록 249개 상태에서 앱이 죽고 화면에 null이 떠 있었다. JVM 테스트로 원리적으로 못 재는 층을 문서화하고, 돌연변이 182건으로 검사가 실제로 빨개지는지 매번 확인했다.

근거 · 진행.md (31)(38)(41)

05실행 방법

둘 중 하나면 된다.

방법 1 — APK 설치 (가장 빠름)

Releases에서 catchflower-v1.0.apk를 안드로이드 폰으로 내려받아 설치한다. 설정 → 보안 → 출처를 알 수 없는 앱을 허용해야 한다.

방법 2 — 소스에서 빌드

git clone https://github.com/Aaron-HyoSan/catchflower.git
cd catchflower/android
cp local.properties.template local.properties   # 키를 채운다
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
키가 없어도 앱은 죽지 않는다. 판별은 Mock으로, 지도·장소명은 꺼진 상태로 돈다. 실제 판별을 보려면 local.properties에 PlantNet·카카오·Supabase 키를 넣는다.

지도는 키해시 등록이 필요하다. 카카오 콘솔에 빌드에 쓴 키스토어의 SHA-1을 등록하지 않으면 vector/auth가 401을 주고 타일이 안 그려진다. 그래서 배포 APK는 키해시가 등록된 디버그 키로 서명했다 — release 키로 다시 서명하면 지도만 조용히 죽는다.

그래서 이 APK는 스토어 버전과 함께 깔리지 않는다. 패키지 이름과 versionCode가 같은데 서명이 다르기 때문이다 (CN=Android Debug vs CN=CatchFlower). 나중에 Play에서 받으려면 이 APK를 먼저 지워야 하고, 지우지 않으면 설치가 실패하면서 화면에는 이유가 나오지 않는다. 도감 기록은 계정이 달라 옮겨지지 않는다.
