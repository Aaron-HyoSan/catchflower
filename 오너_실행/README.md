# 오너가 직접 해야 하는 것 2가지

개발자(클로드)가 할 수 없는 것만 모았다. **둘 다 각각 5분이면 끝난다.**

| # | 할 일 | 어디서 | 이게 없으면 | 급한가 |
|---|---|---|---|---|
| **1** | DB 스키마 적용 | Supabase 대시보드 | **랭킹이 영원히 더미다.** 기록이 기기에만 남는다 | **지금 바로** |
| **2** | 카카오 키 해시 등록 | 카카오 개발자 콘솔 | 지도 화면(13~16)을 붙일 때 막힌다 | 나중에 해도 된다 |

둘은 서로 무관해서 **순서는 아무래도 좋다.**

⚠️ **2번은 급하지 않다.** 확인해 보니 **지도 SDK가 아직 앱에 안 붙어 있다**
(`ui/map/` 폴더가 없고 카카오맵 의존성도 없다 — 화면 13~16은 미구현이다).
지금 등록해도 확인할 화면이 없으니 **1번만 먼저 해도 충분하다.**
지도 작업을 시작할 때 필요해서 미리 계산해 둔 것이다.

지금 **동작 중인 카카오 기능은 REST 키를 쓰는 장소명 조회**뿐이고
(촬영 화면의 `성동구 성수동1가`), **그건 키 해시가 필요 없다** — 이미 잘 돌고 있다.

## 1. DB 스키마 적용 (Supabase)

**왜 내가 해야 하나.** 앱이 쓰는 `anon` 키에는 표를 만들 권한(DDL)이 없다.
일부러 그렇게 뒀다 — 앱이 표를 만들 수 있으면 **누구나 남의 표를 지울 수도 있다.**
표를 만드는 건 대시보드에 로그인한 사람만 할 수 있고, 그게 오너다.

### 순서

1. https://supabase.com/dashboard 접속 → 프로젝트 `ngfkkazyvbbhrcznqkar` 선택
2. 왼쪽 메뉴 맨 아래쯤 **`SQL Editor`** (아이콘이 `>_` 모양) 클릭
3. **`+ New query`** 클릭
4. 이 폴더의 **`01_스키마_전체.sql`** 파일을 열어 **전체 선택(⌘A) → 복사(⌘C)**
5. SQL Editor 창에 **붙여넣기(⌘V)**
6. 오른쪽 아래 **`Run`** 클릭 (또는 `⌘Enter`)
7. 몇 초 기다린다. 200종 데이터를 넣으므로 조금 걸린다

### ⚠️ "Success. No rows returned"는 성공했다는 뜻이 **아니다**

**아무것도 만들지 않고 끝났을 때도 똑같은 메시지가 나온다.** 그래서 세어서 확인한다.

8. **`+ New query`** 로 새 창을 열고 **`02_적용확인.sql`** 을 똑같이 붙여넣고 `Run`
9. 표가 나오는데 **`판정` 칸이 5줄 전부 ✅ 여야 한다**

| 항목 | 실제 / 기대 | 판정 |
|---|---|---|
| 표(table) 6개 | 6 / 6 | ✅ |
| 꽃 도감 200종 | 200 / 200 | ✅ |
| 함수(function) 10개 | 10 / 10 | ✅ |
| RLS 켜진 표 6개 | 6 / 6 | ✅ |
| 접근정책(policy) 17개 | 17 / 17 | ✅ |

**하나라도 ❌ 가 있으면 그 줄을 그대로 캡처해서 보여주면 된다.**

### 실수해도 괜찮다

- **두 번 돌려도 안전하다.** 이미 있는 건 건너뛰고 데이터는 덮어쓰도록 썼다
  (`if not exists` · `create or replace` · `on conflict do update`)
- **중간에 빨간 에러가 나도 앞부분은 남는다.** 고친 뒤 그냥 다시 `Run` 하면 된다
- 붉은 글씨가 떠도 **그 메시지를 그대로 보여주면 된다.** 지우거나 되돌릴 필요 없다

### 이 SQL이 뭘 하나 (궁금하면)

- 표 6개: 꽃 도감 200종 · 사용자 · 발견기록 · 친구 · 차단 · 신고
- 랭킹 함수 4개: **랭킹을 서버가 센다.** 앱이 세면 숫자를 조작할 수 있다
- 접근정책 17개: **남의 기록을 못 보게 하는 규칙.** 비공개 기록은 본인만,
  친구공개는 서로 수락한 친구만 보인다

## 2. 카카오 키 해시 등록

**왜 내가 해야 하나.** 카카오 콘솔은 앱 소유자 계정으로 로그인해야 들어간다.

**키 해시란.** "이 앱이 정말 그 앱인가"를 카카오가 확인하는 지문이다.
등록 안 하면 지도를 불러도 **`잘못된 앱 키`** 로 거부된다.

### 등록할 값 (이 맥의 디버그 키 해시)

```
Vbb1YnBobsq+CLwfh3xnNgVs6a8=
```

끝의 `=` 까지 **그대로 복사**한다. 이건 비밀값이 아니라 공개해도 되는 지문이다.

### 순서

1. https://developers.kakao.com 로그인
2. 상단 **`내 애플리케이션`** → **네이티브 앱키가 `3bf6d46…65e` 로 시작/끝나는 앱** 선택
   - 앱이 여러 개면 각 앱의 `앱 키` 메뉴에서 네이티브 앱키 앞 7자리를 대조한다
   - (이 문서는 git에 올라가므로 **앱키 전체는 적지 않았다.** 전체 값은
     `android/local.properties`의 `KAKAO_NATIVE_APP_KEY` 에 있다 — 그 파일은 커밋되지 않는다)
3. 왼쪽 **`앱 설정` → `플랫폼`**
4. **`Android`** 쪽 **`수정`** (없으면 `Android 플랫폼 등록`)
5. 두 칸을 채운다:
   - **패키지명**: `com.catchflower.app`
   - **키 해시**: 위 `Vbb1YnBobsq+CLwfh3xnNgVs6a8=`
6. **`저장`**

### ⚠️ 이 키 해시는 **이 맥에서만** 통한다

키 해시는 **서명 키의 지문**이라 기기가 아니라 **빌드한 컴퓨터**에 딸린다.

| 상황 | 필요한 것 |
|---|---|
| 지금 이 맥에서 개발·테스트 | 위 값 하나로 끝 |
| 다른 맥에서 빌드 | 그 맥의 값을 **추가로** 등록 (여러 개 등록 가능) |
| 스토어 출시 | **출시용 키 해시를 따로 등록해야 한다.** 디버그 값으로는 출시 앱이 안 된다 |

출시할 때가 되면 그때 다시 계산해 드리겠다 — **지금 미리 할 필요는 없다.**

다른 맥에서 직접 뽑고 싶으면:

```
keytool -exportcert -alias androiddebugkey \
  -keystore ~/.android/debug.keystore \
  -storepass android -keypass android \
  | openssl sha1 -binary | openssl base64
```

## 끝나면

**1번이 끝나면 알려주면 된다** — 서버 업로드를 붙여서 랭킹을 실제 숫자로 바꾼다.

2번은 지도 화면을 만들 차례가 오면 그때 하면 된다 (지금 해 둬도 손해는 없다).

### 참고 — 이 두 개 말고 답만 주면 되는 것 3가지

코드가 아니라 **판단**이 필요한 것들이다. `프로젝트 맥락/오너_결정사항.md`가 원본이고,
**"전부 권고대로"** 한 줄이면 끝난다.

| 번호 | 무엇 | 권고 | 안 정하면 |
|---|---|---|---|
| **B-4** | 유사종 10그룹 통합 | 전부 통합 (200종 유지) | AI가 원리적으로 못 가르는 종이 남아 **영원히 못 채우는 칸**이 생긴다 |
| **B-3-a** | 신뢰도 하한(floor) | **0.05로 낮춘다** | 현행 0.30은 **정답 66장을 버리고** 오답 9장만 막는다 |
| **B-3-b** | 난이도 임계값 | 실측 분위 기준으로 낮춘다 | 위와 같은 이유 |
| 미발견 셀 | 회색 처리 방식 | (b) 단색 실루엣 | 200칸 대부분이 미발견이라 **첫인상을 좌우한다** |
