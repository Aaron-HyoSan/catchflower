## 4. 협업 방식

### 4-1. 형상 관리

| | |
|---|---|
| 저장소 | https://github.com/Aaron-HyoSan/catchflower (공개) |
| 브랜치 | `main` |
| 커밋 | **42개** (2026-08-04 ~ 08-10) |
| 커밋 규칙 | `[iOS]` / `[AOS]` / `[공용]` 접두 — 어느 플랫폼 변경인지 제목에서 보인다 |

### 4-2. iOS · Android 동시 개발을 어떻게 어긋나지 않게 했나

터미널(작업 세션) 2개를 병행했다. 같은 서버·같은 DB를 쓰므로 **한쪽이 필드명을 바꾸면
다른 쪽이 조용히 깨진다.** 그래서 문서 하나를 상위 규칙으로 뒀다.

| 문서 | 역할 |
|---|---|
| `공유계약_iOS_AOS.md` | DB 컬럼명 · enum 문자열 · 정책 숫자 · Mock 동작. **혼자 못 바꾼다** |
| `세션시작_iOS.md` / `세션시작_AOS.md` | 새 작업 세션이 **가장 먼저** 읽는다 (환경 · 금지사항) |
| `구현현황_iOS.md` / `구현현황_AOS.md` | 지금 무엇이 되고 **무엇이 안 되나** |
| `진행.md` | 스텝이 끝날 때마다 덧붙인다 — **무엇을 했는지가 아니라 무엇이 틀렸는지** |

실제로 한쪽이 `ai_confidence`를 Double로 넓혀 다른 쪽 파싱이 깨진 일이 있었고,
그 뒤로 **계약 문서를 고치고 기록한 다음에만 코드를 고치는** 순서로 굳혔다.

### 4-3. 의사 결정 기록

정책 **35항목**을 `오너_결정사항.md`에 모아 두고, 확정된 것만 코드에 반영했다.
예: 판별 실패 floor **0.05**는 실측 근거를 붙여 승인받은 값이고, iOS·Android 공용
계약값이라 **어느 한쪽이 혼자 바꿀 수 없다.**
