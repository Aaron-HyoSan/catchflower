> 🔴 **51초짜리를 "잘렸다/빠졌다" 없이 만드는 데 두 번 걸렸다.** 첫 컷 목록은
> **분석중 로딩 컷을 통째로 빠뜨리고**(아래 ⚠️가 금지한 그것) **검은 프리뷰 2초**를
> 앞에 붙였다 — 카메라가 고장난 것처럼 보였다. 그런데도 `43.0초 · passthrough 성공`이
> 초록으로 떴다. **길이와 "성공"은 무엇이 들어갔는지 말해 주지 않는다.**
> 그래서 `trim_play_video.py`는 자른 뒤 **프레임을 다시 뽑아 시트로 묶는다**(사람이 읽는다).
> 구간은 그 스크립트 `CUTS`에 초 단위로 적혀 있다 — **다시 녹화하면 전부 틀어지니
> `--frames-only`로 경계를 먼저 다시 읽는다.**

> 🔵 **이 문서가 "에뮬레이터로는 찍을 수 없다"고 말했던 것은 틀렸다.**
> 에뮬레이터 `virtualscene` 카메라는 3D 방 **벽에 임의의 사진을 걸 수 있고**
> (`adb emu virtualscene-image wall <파일>`), 앱은 그것을 **진짜 카메라 파이프라인으로
> 촬영**한다. 그래서 ML Kit 1차 필터·개화월 압축·PlantNet 실호출이 전부 실제로 돈다.
> **앱 코드도 안 고치고 QA 우회 스위치도 안 켰다.** 실측 로그:
> `1차필터: 꽃=true conf=0.937` → `후보=98개 (8월)` → `Taraxacum 0.239 → 통과=2`.
> 함정 3개(AVD config·포스터 벽·개화월)는 스크립트 docstring에 적어 뒀다.

> ⚠️ **실물 꽃로 다시 찍고 싶으면** 아래 2~4절이 그대로 유효하다(오너용 절차).
> 실기기 영상이 더 설득력 있지만, **제출 요건은 이미 충족된다.**

## 2. 촬영 전 준비 — 5분

### 2-1. 꽃 준비

| | |
|---|---|
| **한 송이가 화면을 꽉 채울 수 있는 꽃** | 멀면 AI 정확도가 떨어진다 |
| **8월에 피는 꽃** | 개화월 하드 필터 때문에 8월 후보는 **98종**뿐이다. 봄꽃을 찍으면 화면 12(실패)가 뜬다 |
| 추천 | 나팔꽃 · 무궁화 · 백일홍 · 코스모스(초가을) · 해바라기 · 봉선화 · 채송화 |
| 조명 | **낮 · 자연광 · 역광 피할 것** |

> 🔴 **모니터 속 꽃 사진은 안 된다.** 디스플레이 서브픽셀이 모아레를 만들어
> 온디바이스 필터가 `Pattern`으로 읽는다 — `꽃이 아닐 수도 있어요`가 뜬다.
> (이건 결함이 아니라 필터가 제대로 도는 것이다.)

### 2-2. 앱 상태 만들기

**도감이 비어 있으면 컷 2가 심심하고, 꽉 차 있으면 컷 6의 "신규 등록"이 안 뜬다.**
**3~5종 정도 발견된 상태**가 가장 좋다. 지금 계정이 이미 그 상태다.

| 확인 | 어떻게 |
|---|---|
| 활동 지역이 정해져 있나 | 마이 화면에 `성수2가3동` 같은 동 이름이 보이면 됨 |
| 도감에 3~5칸 색이 있나 | 도감 홈 상단 `3 / 200종` |
| 카메라·위치 권한 허용됨 | 촬영 화면이 바로 열리면 됨 |
| **찍을 꽃이 도감 200종에 있나** | 없으면 화면 12가 뜬다. 위 추천 목록 중에서 고르면 안전 |

### 2-3. 방해 요소 끄기

- **알림 끄기** (방해금지 모드) — 배너가 화면 위에 뜨면 다시 찍어야 한다
- **화면 자동 회전 끄기** (세로 고정)
- **배터리 절전 끄기** — 카메라·네트워크가 느려진다
- 상태바에 개인정보가 없는지 확인 (와이파이 이름 등)

## 3. 녹화 방법

### 방법 1 — 폰 자체 화면 녹화 (권장)

삼성 기기: **빠른 설정 → 화면 녹화**

| 설정 | 값 |
|---|---|
| 소리 | **없음** 또는 미디어 소리 (마이크는 끈다 — 주변 소음이 들어간다) |
| 화질 | **고화질(1080p)** |
| 셀피 비디오 | 끔 |

**장점:** 케이블이 필요 없고 야외에서 바로 찍는다. **실물 꽃을 찍어야 하므로 이게 맞다.**

### 방법 2 — `adb screenrecord` (케이블 연결 시 · 내가 실행한다)

폰을 맥에 꽂으면 내가 아래를 돌린다. 시간·해상도·비트레이트가 고정돼 재현이 된다.

```bash
# 최대 60초 · 1080p · 8Mbps
adb -s R5CX21QNVVN shell screenrecord \
  --time-limit 60 --size 1080x2340 --bit-rate 8000000 \
  /sdcard/catchflower_play.mp4

# 녹화가 끝난 뒤 꺼낸다
adb -s R5CX21QNVVN pull /sdcard/catchflower_play.mp4 ~/Downloads/
adb -s R5CX21QNVVN shell rm /sdcard/catchflower_play.mp4
```

⚠️ **`screenrecord`의 제약을 미리 안다.**

| 제약 | 결과 |
|---|---|
| **최대 3분** | 50초 목표라 문제 없다 |
| **소리가 안 들어간다** | 어차피 자막 중심이라 무관 |
| `--time-limit` 없으면 3분에서 잘린다 | 항상 명시한다 |
| **Ctrl+C로 끊으면 파일이 깨질 수 있다** | `--time-limit`가 끝나기를 기다린다 |
| 케이블이 꽂혀 있어야 한다 | **야외 실물 꽃 촬영에는 방법 1이 낫다** |

## 4. 촬영 순서 (실전)

```
① 야외에서 꽃 앞에 선다 → 화면 녹화 시작
② 앱을 켠다                          ← 컷 1
③ 도감을 위아래로 한 번 스크롤        ← 컷 2 (3초)
④ 하단 '꽃 촬영' 탭 → 꽃을 네모에 채워 셔터  ← 컷 3
⑤ 로딩이 끝날 때까지 화면을 그대로 둔다 ← 컷 4 (자르지 말 것)
⑥ 후보에서 맞는 꽃을 손가락으로 고른다  ← 컷 5
⑦ 등록 화면을 2~3초 보여준다          ← 컷 6
⑧ 지도 공유 → 공개 범위 고르고 저장    ← 컷 7
⑨ 지도 탭 → 핀 확인                  ← 컷 8
⑩ 랭킹 탭 → 순위 확인 → 녹화 종료      ← 컷 9
```

**한 번에 다 못 찍어도 된다.** 컷을 나눠 찍고 나중에 이어붙이면 되고, 실제로
④~⑦(촬영→등록)만 한 번에 이어져 있으면 충분하다.

### 실패했을 때 — 원인이 화면에 안 보인다

`어떤 꽃인지 알 수 없었어요`(화면 12)가 뜨면 **원인이 세 가지인데 화면은 같다.**
폰을 맥에 꽂아 주면 내가 로그로 갈라 준다.

```bash
adb -s R5CX21QNVVN logcat -d -s CatchFlower
```

| 로그 | 원인 | 다시 찍으면 되나 |
|---|---|---|
| `1차필터: 꽃=false` | 온디바이스 필터가 막았다 (화면 사진 · 너무 멀다) | **꽃을 크게 다시** |
| `판별 호출 직전`은 있고 `판별 응답`이 없다 | 네트워크·타임아웃 | 신호 확인 후 재시도 |
| `판별 응답: … 학명 매칭 0종` | PlantNet 답이 **도감 200종에 없다** | **다른 꽃로 바꾼다** (도감 한계) |
| `화면 12: 원인=ⓒ` | 점수가 floor 미달 | 더 선명하게 다시 |
